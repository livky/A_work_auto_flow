# 工具与脚本规则

## 组织方式

- 文件读写、清洗、绘图、通用数值函数、接口适配和脚本功能属于工具；模块化实现不构成核心算法收录资格。只有公司算法/模块文档定义的关键模型算法进入 core-algorithms，工具可引用其 MOD-ID。

- `registry.json` 登记所有稳定工具、Owner、用途、输入输出、状态和验证命令。
- `scripts/` 适合单文件/小型 CLI；`packages/` 适合可测试库；`external/` 只放适配器和接入说明。
- 算法核心、数据 IO、编排与展示分层，避免第三方平台锁定核心逻辑。

## 工具质量门

- 有清晰 CLI 与 `--help`；输入输出、单位、默认值和失败语义明确。
- 配置优先于硬编码路径；凭据只从批准的环境或秘密管理注入。
- 涉及批量写入时支持 `--dry-run`、幂等或可恢复策略。
- 结构化日志至少包含 tool/version、run_id、输入数据 ID、参数摘要、状态和耗时。
- 对数值算法测试正常、边界和已知失效路径；容差有工程依据。
- 代码注释解释意图、假设与危险边界，不写无意义逐行注释。

## 晋升与退役

- 具有稳定输入输出和复用价值的脚本登记为工具，按风险验证；不因简单文档整理机械增加测试。
- 外部工具先写 adapter 与数据/权限边界，再在批准环境中启用。
- 退役工具保留迁移说明和替代项，注册表状态改为 `deprecated`，不要静默删除历史 Run 依赖。
