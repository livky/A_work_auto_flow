# 报告生产

## 原则

- PPT、Word、PDF 和周报引用可追溯证据；未复核结果可以用于明确标注限制的草稿，不能冒充已批准结论。报告不是新事实源。
- 先写 `briefs/` 中的受众、决策、信息层级和截止时间，再选择格式。
- 关键数字、表格和图表引用固定 `RUN-*` 与产物，不手工复制无法追溯的数值。
- 报告源、参数、模板版本、引用、生成时间和产物哈希进入 report manifest。
- 对外或安全关键内容必须人工审阅；短报告应全页视觉检查，长报告至少检查封面、密集页、关键图、表格、引用与结尾。

## 推荐结构

```text
reports/
├─ briefs/       # 任务与受众 brief
├─ sources/      # Markdown/Quarto/脚本等可执行源
├─ templates/    # 公司批准模板、字体/色板说明
├─ manifests/    # 报告到 Run/数据/模板的映射
└─ generated/    # 生成件；默认不进 Git，保留批准版本策略另定
```

首次获得公司 PPT/Word 模板后，使用对应文档/演示技能建立经过渲染验证的模板，而不是仅复制主题色。
