## 一、目标与已经确定的边界

本次改造将持续记录、经验提取、跨问题检索和研究续接做成一套共享能力，接入现有 Research、Run、Project、证据系统和工作台。

实施采用增量改造：保留现有业务对象和证据身份，分批增加能力。每批有独立验收条件，并保存可供下一次任务直接续接的执行记录。

已经确定以下产品决策：

- **Research 默认开启持续探索；Run 默认采用基础记录；Project 可选择开启。** 三者共用底层机制，均可按需要使用全部记忆层。
- **记录粒度由信息价值决定。** 耗时长、数据大不自动意味着需要复杂过程记录；有价值的结论、失败边界和决策依据应独立保留。
- **检索以“按问题发现有价值的局部摘要”为主。** 局部成果无需先晋升为全局知识，才能被其他研究发现。
- **摘要、可信度、可检索范围分别管理。** 保存、形成摘要、扩大发现范围，都不代表结论已经验证。
- **首版包括 CLI、Skill 和现有工作台。**
- **由当前协作 AI 执行提取、整理和研究判断。** 本地程序负责结构校验、版本管理、保存、检索和证据检查；首版不另接模型服务。
- **自主推进仅发生在当前任务内。** 用户授权后可以连续推进；退出前保存断点，下次用户要求时续接，不增加后台调度。
- **先保存实际可取得的研究记录。** 不承诺捕获所有平台的完整聊天；不能取得的原始内容明确标记缺失。

本方案中的编号统一为：L0 原始材料、L1 事件与结果、L2 经验、L3 研究地图。现有上下文装载阶段另称“聚焦、调查、扩展”，避免两个体系共用 L0/L1/L2 名称。

## 二、对象关系与存储设计

### 2.1 四层能力与现有对象的对应关系

| 层次 | 保存内容 | 与现有框架的关系 |
|---|---|---|
| L0 原始材料 | 已获准的文档、代码版本、配置、实验产物、可取得的对话和关键输出 | 复用来源登记、Run 输入和产物；外部原件仍在获批位置 |
| L1 事件与结果 | 问题、尝试、参数、观察结果、决策、依据、限制、未决问题 | Run 本身就是一种事件与结果；不再为每个 Run 建一份重复 Event |
| L2 经验 | 可迁移的方法、问题结构、失败模式、适用与禁用条件 | 可以属于单个 Run、Research 或 Project；经复核后按现有知识规则共享 |
| L3 研究地图 | 当前目标、路线、关键结论、冲突、未决问题和导航链接 | 按对象或主题维护多个有界地图，不建立不断追加历史的总摘要 |

补充规则：

1. **事件与结论分开。** 一个 Run 可以产生多条有独立价值的结论，每条可单独形成检索摘要。
2. **只在没有合适 Run，或决策横跨多个 Run 时建立独立 Event。**
3. **允许跨层引用。** 经验可以直接引用原始证据，不强制补造中间事件。
4. **四层按需生成。** 不为每个对象预建四套空文件夹。
5. **核心算法准入保持原规则。** 新记忆引擎、检索脚本和一般研究经验不因此进入 `core-algorithms`。

### 2.2 文件事实源与派生索引

采用“现有业务文件＋对象所属记忆记录＋统一派生登记”的布局：

| 位置 | 职责 |
|---|---|
| 现有 Research、Run、Project 目录 | 继续保存业务对象、已有说明和正式证据 |
| 各对象下按需创建的 `memory/` | 保存策略、独立事件、经验、问题、路线、摘要表示、检查点及版本历史 |
| `knowledge/maps/` | 保存跨对象的主题导航地图，仅引用规范对象与版本 |
| 现有 `retrieval/` 体系 | 保存配置、反馈、会话记录及可重建的统一目录、全文与向量索引 |
| `.local/` | 仅保存锁、临时文件和运行缓存，不保存唯一一份长期记忆 |

具体约定：

- 每条新增记录只有一个规范归属对象；其他 Research/Project 通过引用使用。
- 归属不等于只能在该对象内检索。
- 统一登记表由现有对象元数据和各对象记忆入口重建，不成为第二份业务事实源。
- 长期记录使用 JSON 结构字段与配套 Markdown 正文；两者的职责由契约明确，正文不在多个字段间重复维护。
- 当前地图和人类阅读视图可以重新生成；其引用的记录与历史版本必须保留。
- 共享已有经验时，默认建立指向规范记录的知识入口。只有形成了新的、更一般化的命题，才建立新的经验或知识正文，并记录来源和独立复核状态。

### 2.3 身份、版本与提交

保留现有 `RUN/RES/PRJ/MOD/CLM/EVD` 身份；新增事件、经验、问题、路线、地图、检查点和检索表示分别使用稳定的类型前缀 ID。ID 不随标题、目录显示名或摘要措辞变化。

新增记忆记录采用：

- 稳定记录 ID。
- 单调递增修订号。
- 内容指纹。
- 前一修订引用。
- 变更人、时间、原因与输入版本。
- 每个归属对象一个当前版本入口。

保存顺序固定为：

1. 校验结构、归属、引用与权限。
2. 写入新的不可变记录版本。
3. 检查预期旧版本。
4. 原子切换当前版本入口。
5. 更新派生索引；失败则报告“记录已保存、索引待更新”。

首版以**单个归属对象**为一次记忆事务的边界。跨对象关系只在一个规范位置保存，反向关系由索引生成，避免多处同步写入。

涉及现有 Run 或复核 manifest 时，先完成既有证据写入，再提交引用它的记忆记录。中途失败保留已完成结果和可重试回执，不删除已经产生的证据。

## 三、记录契约、可信度和自动整理规则

### 3.1 核心接口类型

所有入口使用同一组版本化契约，CLI、工作台和 Skill 不各自实现字段规则。

| 类型 | 必需内容 |
|---|---|
| `OwnerRef` | 对象类型、稳定 ID；路径由登记表解析 |
| `SourceRef` | 来源 ID、固定版本或指纹、定位信息、可访问状态、取得方式 |
| `MemoryRecord` | ID、类型、归属、修订、正文/结构字段、保存原因、来源、时间与作者 |
| `ResearchEvent` | 问题、约束、重要尝试、观察结果、决策及依据、限制、关联 Run |
| `Experience` | 问题结构、经验主张、适用条件、不适用条件、失败模式、触发问题、来源 |
| `OpenQuestion` | 问题、影响的决策、缺失证据、关联对象、状态、解决依据 |
| `Route` | 目标版本、路线假设、尝试引用、当前障碍、下一步、关闭与重新开启条件 |
| `Representation` | 规范对象与版本、表示类型、摘要文本、适用边界、生成来源 |
| `Association` | 两端对象、关系类型、解释、类比限制、生成依据及处理状态 |
| `Checkpoint` | 目标版本、当前路线、已完成事项、待办、阻碍、关键引用、下一步和预算 |
| `MemoryPacket` | 查询、范围、候选、实际装载、证据角色、命中原因、缺失项、预算与版本 |

字段边界：

- 未知信息允许为空，但必须能区分“未知”“不适用”“未取得”。
- AI 的文字理由保存为可核对的决策依据，不保存私有思维链。
- 新经验包含可检验主张时使用现有 `CLM` 结论模型；不另建一套“经验可信度”替代复核系统。
- 摘要不是新证据对象，不能独立获得一份重复的科学复核。
- `confidence` 如保留，仅表示生成者的判断及依据，不作为正式使用门槛。

### 3.2 修复动态记录与证据指纹之间的耦合

当前证据复核会绑定所属对象内容；直接向 Research/Run 元数据不断加入推进状态，可能导致已复核结论无关失效。

本次采用以下处理：

- 新增推进状态、记录策略、检查点、检索摘要放入记忆侧记录。
- 日常保存记忆不改写旧 manifest 的 `updated_at`、执行状态、输入、参数和结论。
- 新记忆结论绑定自身内容及明确引用的目标、输入和证据版本，不绑定整个研究的动态进度。
- 现有旧指纹继续按原规则解释，不批量重算并覆盖历史复核。
- 实际修改旧结论、输入或适用范围时，仍触发原有失效检查。
- 首版不自动迁移旧复核语义；发现旧记录已有版本不一致时如实提示。

证据图增加新增记忆记录的读取适配器，共用已有复核、依赖传播和正式使用检查。

### 3.3 三种记录配置

| 配置 | 默认对象 | 行为 |
|---|---|---|
| 基础记录 | Run | 保存输入、结果、限制及必要断点；有价值的结果形成摘要 |
| 结果积累 | 用户选择 | 对多条结果、失败边界和决策分别建立可检索入口，过程适度汇总 |
| 持续探索 | Research；开启后的 Project 可选 | 增加目标版本、路线、未决问题、阶段综合和续接检查点 |

每个对象支持以下显式覆盖：

- 必须保留的内容。
- 过程记录粒度。
- 是否自动提取结果摘要和经验候选。
- 是否允许工作区范围发现摘要。
- 是否允许根据价值自动增加记录深度。
- 地图与检查点的生成策略。

优先级固定为：本次用户明确要求 → 对象显式配置 → 对象类型默认 → 工作区默认。

AI 可以自动增加记录深度，并记录原因。降低后续记录粒度不删除既有材料，不取消用户明确的保留要求。

### 3.4 价值触发与巩固

以下变化触发保存或更新：

- 改变下一步决策、参数选择或路线。
- 产生可独立引用的结果。
- 排除一种方法或限定适用范围。
- 发现重复失败模式或关键反例。
- 形成可迁移的方法建议。
- 出现影响决策的未决问题。
- 用户明确要求保留。

时间、工具调用次数、文件大小仅辅助安排检查点，不作为价值判断。

整理分为两个节奏：

- **即时记录：**实质变化后保存结果、失败、决策和引用；摘要可立即建立。
- **阶段巩固：**路线切换、里程碑、任务结束或用户要求时，检查受影响经验和地图。

巩固不能通过把旧摘要全文嵌入新摘要的方式累计历史。没有新证据或变化时应为幂等操作。

### 3.5 失败、冲突和未决问题

失败记录至少区分：

- 执行或环境失败。
- 在给定条件内未取得改进。
- 有界反例或反证。
- 证据不足、暂时无法判断。

每条重要失败保存测试范围、结果、不能推出什么、再次尝试条件。一次失败不能自动变成普遍不可能结论。

问题状态使用 `open / investigating / blocked / resolved / superseded`。解决问题必须引用答案或明确决策依据；“任务执行完毕”不自动解决研究问题。

沿用 `not-reviewed / accepted / disputed / retracted / superseded` 复核状态。新冲突先作为冲突候选记录；确认影响后，通过现有复核接口处理，并传播到依赖结论、摘要、地图和报告入口。

失败 Run 仍保留既有正式使用限制，不能借助摘要或经验层绕过检查。

## 四、问题驱动检索与跨研究关联

### 4.1 多表述索引

有价值的原始材料、事件、结论、经验和问题都可以拥有检索表示，不要求先生成 L2 经验。

每个规范对象最多维护以下六类表示：

1. 标题。
2. 结果摘要。
3. 问题结构。
4. 触发问题。
5. 失败表现。
6. 适用与禁用边界。

一类表示合并存储，不按每个触发问题无限增加向量。修改表示只更新相关对象的表示版本。

同一结论的多个表示先按规范对象归并，再参与排序，不能靠摘要数量增加证据数量或获得重复排名优势。

### 4.2 检索流程

默认流程为：

1. 确定问题、当前对象、可访问范围和明确排除项。
2. 并行取得现有全文候选、记忆关键词候选和向量候选。
3. 按规范身份归并重复表示。
4. 结合当前目标、路线和问题匹配度选择直接命中。
5. 从少量直接命中沿关联图进行有界扩展。
6. 回源检查版本、复核、适用范围和冲突。
7. 输出有界 `MemoryPacket`；需要时再展开事件与原始证据。

首版沿用现有 RRF 排名融合思想，不直接叠加不可比较的 BM25、向量分数和“重要性”分数。记录各通道排名和关联路径，便于评价与调参。

使用次数和时间仅作为弱排序因素，不能使高频错误结论压过更相关的新证据。

### 4.3 跨对象发现的层级

| 关联对象 | 默认用途 |
|---|---|
| 经验 ↔ 经验 | 相同问题结构、方法前提和失败模式 |
| 结论/事件 ↔ 结论/事件 | 发现尚未一般化、但可能有参考价值的局部成果 |
| 问题 ↔ 证据或经验 | 为未决问题发现答案候选 |
| 地图 ↔ 上述对象 | 导航与组织，地图自身不作为独立证明 |

摘要发现范围分为：

- `owner_only`：仅所属对象。
- `workspace_summary`：在获准工作区范围内按问题发现摘要。

自动生成的有价值摘要默认允许 `workspace_summary`，但仍受既有来源权限、敏感性与用户排除约束。该设置不授予读取新来源的权限。

跨对象首先加载摘要和边界；正文与原件仅在相关且权限允许时展开。不因共同属于某个 Research/Project 而装载全部内容。

### 4.4 关联图与证据图分工

新增关联类型：

`derived_from`、`refines`、`same_problem`、`same_failure_mode`、`prerequisite`、`analogous_to`、`used_in`。

规则固定为：

- `supports/input/contradicts/background` 的证据语义继续由现有证据系统处理。
- `derived_from` 表示来源沿袭，不等于支持命题。
- `analogous_to` 必须说明共同结构和不能迁移的部分。
- 自动相似度只能提出候选关联，不能自动建立科学支持关系。
- 人或 AI 可以接受一条导航关联；这不改变两端结论的复核状态。
- 同一条证据关系只保存一次；工作台和检索图读取同一投影。

图扩展首版采用受限邻接遍历：默认一跳，经过上下文反馈最多两跳，优先检查直接命中的邻居。暂不引入全图 PageRank 排名。

### 4.5 上下文预算与角色

沿用“聚焦—调查—扩展”三阶段和最多两次扩展：

| 阶段 | 最多规范候选 | 其中跨对象候选上限 |
|---|---:|---:|
| 聚焦 | 6 | 2 |
| 调查 | 14 | 4 |
| 扩展 | 24 | 8 |

这些是上限，不要求填满。首版记忆包默认字符预算为 16,000，并受工作区更小的硬上限约束；用户可显式调整。自动扩展不增加总预算。

`MemoryPacket` 分开呈现：

- 当前目标与约束。
- 范围内通过检查的证据。
- 未复核结果与经验候选。
- 类比启发及迁移限制。
- 失败、反证和冲突。
- 未决问题。
- 来源定位、遗漏项和展开建议。

不得只截取建议、丢掉其禁用条件。预算不足时应省略完整条目或返回明确的精简表示，并登记省略原因。

正式查询继续使用现有严格证据门槛；探索查询可以显示候选、历史失败和被撤回记录，但须保留状态。

### 4.6 反馈闭环

复用现有上下文反馈，增加：

- 应召回但未召回。
- 命中但不相关。
- 类比边界不成立。
- 摘要遗漏关键条件。
- 证据版本过期。
- 实际采用及采用结果。

反馈引用查询 ID、记录版本和判断依据。先修正表示、关系或检索策略；不能仅因“被采用”自动提升科学可信度。

## 五、持续研究、Skill、CLI 与工作台

### 5.1 目标版本与研究续接

目标允许演进，但每次修改保存：

- 前后目标版本。
- 修改原因和用户约束。
- 对成功标准、路线和既有结果适用性的影响。
- 哪些结论仍适用，哪些需要重评。

旧结果继续绑定当时目标，不将新目标回填到旧尝试。

恢复任务时按顺序加载：

1. 当前目标和用户约束。
2. 最新检查点。
3. 当前路线和未决问题。
4. 上次以来变化或失效的关键证据。
5. 与下一步直接相关的结果和经验摘要。

只有发现明确缺口才进一步展开历史。检查点记录的是当时状态，恢复时必须重新检查关键来源版本和复核状态。

### 5.2 当前任务内自主推进

一次自主推进遵循：

“检查断点 → 选择一个有依据的下一步 → 执行 → 保存结果 → 检查反证和停止条件 → 决定是否继续”。

默认上限为 3 个实质推进单元或 45 分钟，以先达到者为准；只在步骤边界检查时间，不能保证中断单个外部工具。用户可以明确指定其他预算。

以下情况停止并保存：

- 达到验收标准或预算。
- 关键证据不可取得。
- 下一步超出已授权范围。
- 出现需要用户选择的目标或资源取舍。
- 重复尝试未改变结果，也没有新的检验理由。
- 用户中止。

当前任务结束后不继续运行。不得把一次“继续研究”解释成永久自主权限。

### 5.3 公共命令与服务接口

新增统一 `memory` 命令组，现有命令继续兼容：

| 命令 | 职责 |
|---|---|
| `memory inspect` | 查看对象策略、当前状态、记录和版本 |
| `memory prepare` | 根据变化返回提取、整理或续接所需的有界输入包 |
| `memory validate-draft` | 校验 AI 提交的结构化草案，不写业务数据 |
| `memory commit` | 使用预期版本提交记录、关系、策略或检查点 |
| `memory search` | 问题驱动发现，返回候选及原因 |
| `memory expand` | 按 ID、版本和预算展开下层证据 |
| `memory resume` | 生成续接包，不自动执行实验 |
| `memory feedback` | 保存采用、漏召回、错误类比等反馈 |
| `memory migrate` | 预览或执行旧记录适配，生成回执 |
| `memory recover` | 检查中断事务并执行可验证恢复 |

共同约定：

- 提供 JSON 输出、帮助、明确失败码。
- 批量变更支持 `--dry-run`。
- 写入必须包含预期版本及幂等请求 ID。
- 版本冲突返回可比较的当前版本，不自动覆盖用户修改。
- “草案”是技术校验阶段，日常获准记录不要求用户逐次审批。
- `prepare` 不调用独立模型服务；当前协作 AI 读取准备包并提交草案。
- `review-claim` 等现有复核命令继续负责可信状态修改。

工作台通过新增 `/api/v1/memory/*` 路由调用同一服务层，保持已有 API 兼容。请求、响应与前端类型由同一契约源生成。

### 5.4 Skill 组织

扩展现有工作流，不安装整套 MRS 脚本：

- `workspace-context`：增加问题驱动摘要发现、角色区分和渐进展开。
- `context-maintenance`：增加提取、表示更新、关系整理和受影响地图巩固。
- `evidence-inspection`：增加记忆来源链、版本失效和下游影响检查。
- `research-loop`：扩展为记录、路线、目标版本、断点和当前任务内推进的主要入口，并加入可安装入口。

安装器保留用户自定义 Skill；发现同名修改时输出差异和合并建议，不覆盖。

### 5.5 工作台功能

在现有对象详情和关系图基础上增加：

- 对象记录配置与配置来源。
- 当前目标、路线、未决问题和最近检查点。
- 事件、结果和经验列表，可查看保存原因与版本。
- 问题检索及“为何命中”“类比限制”“展开证据”。
- 候选关系处理、冲突提示及既有复核入口。
- 按主题查看的研究地图。
- 续接包生成与复制入口。

首版工作台的“继续研究”生成供当前 AI 使用的续接内容，不显示成浏览器已经启动自主研究。记录是否保存、索引是否更新、结论是否复核分别显示。

## 七、逐批开发与执行顺序

### 7.1 长任务执行档案

实施第一批建立自包含主计划、验收清单和交接记录。建议放在本次框架研究对象中，通过一个主入口链接：

- `PLAN.md`：目标、约束、架构、接口、批次依赖和变更决策。
- `CHECKLIST.md`：逐项状态、实现位置、测试和验收证据。
- `HANDOFF.md`：当前事实、未完成事项、已知故障和精确下一步。
- 批次附件：只存该批契约、测试记录和必要说明，不把全部历史塞入主计划。

每项执行任务必须包含：

`任务 ID、依赖、输入版本、交付物、验收测试、状态、证据位置、剩余风险`。

状态使用：

`planned → active → implemented → verified`，受阻用 `blocked`。

“代码已写”不能直接标记 `verified`；跳过或无法运行的必要测试必须保留为未完成项。

### 7.2 开发批次

| 批次 | 依赖 | 实现任务 | 完成门槛 |
|---|---|---|---|
| **B00：执行基线** | 无 | 建主计划与清单；记录代码版本、环境、现有测试结果和已有问题；明确新功能开关 | 基线问题与本次新增问题可区分；下一批输入完整 |
| **B01：契约与默认策略** | B00 | 固定所有核心类型、ID、引用格式、状态、配置优先级及草案格式 | 契约正反例通过；Python 与前端能使用同一契约 |
| **B02：持久化与恢复** | B01 | 实现对象记忆入口、不可变修订、原子切换、并发控制、幂等和回执 | 中断与并发测试通过；无已提交记录丢失 |
| **B03：旧对象适配** | B02 | 为 Research/Run/Project 建统一读取适配；Run 直接作为事件；旧对象缺新增字段时按默认解释 | 旧数据不改即可读取；无重复 Run/Event；旧命令兼容 |
| **B04：证据系统接入** | B03 | 接入新记录与结论；隔离动态状态；扩展版本、撤回和下游检查 | 动态记录不误伤旧复核；真实证据变化能阻止正式复用 |
| **B05：记录与结果摘要** | B04 | 实现配置、价值触发、准备包、草案校验、即时保存、多结论摘要 | 长而简单的 Run 保持简洁；短而有价值的结果得到独立保留 |
| **B06：路线与断点** | B05 | 实现目标版本、路线、失败边界、未决问题、检查点和恢复包 | 中断后能够恢复下一步；不靠读取全部历史；变更证据有提示 |
| **B07：关键词与多表示检索** | B05 | 接入统一目录和 FTS；创建六类表示；按规范身份归并；复用向量接口 | 无向量时完整基本功能可用；摘要数量不造成排名膨胀 |
| **B08：关联图与跨对象发现** | B04、B07 | 保存类型化关联、候选处理、邻接扩展、范围过滤和命中解释 | 跨问题可发现局部摘要；类比不能冒充支持；扩展有界 |
| **B09：记忆包与反馈** | B06、B08 | 实现角色区分、预算、两级展开、缺失说明、漏召回和采用反馈 | 预算与排除选择在扩展中保持；正式查询不混入不合格证据 |
| **B10：阶段巩固与地图** | B09 | 实现受影响项计算、经验精化、冲突候选和地图更新 | 无变化重复运行幂等；历史不递归堆入当前地图 |
| **B11：CLI 与 Skill 闭环** | B10 | 完成公共命令、帮助、失败码；更新四个工作流；接入 Skill 安装器 | 协作记录及授权自主推进两条完整场景通过 |
| **B12：工作台集成** | B11 | 接入配置、结果、检索、证据、路线、问题、候选和续接 UI | 前后端契约及端到端测试通过；更新预构建资源和指纹 |
| **B13：迁移与 Windows 升级** | B12 | 扩展旧工作区 fixture；补充清单、配置补缺、升级/恢复、缓存和分发边界 | 真实 `setup.cmd` 预览、升级、重复升级、恢复逐项保护检查通过 |
| **B14：整体评价与交付** | B13 | 完整回归、检索评价、长任务演练、README 重整、依赖包与发布验收资料 | 必要验收无未解释失败；源码、资源、依赖和验证记录对应 |

B07 的关键词检索先于向量接入验收；B08 的直接关系读取先于自动候选扩展验收。每个批次内部先完成最小完整行为，再增加扩展能力。

### 7.3 每批结束时的固定动作

1. 运行该批关联测试和要求的回归。
2. 记录结果、实际版本、未提交变更指纹及限制。
3. 更新清单与交接信息。
4. 检查 README 是否需要同步概念或使用方法。
5. 结构性变化后执行索引刷新与校验。
6. 为有独立验证输入和结果的批次建立固定 Run；简单实施子任务在该 Run 中汇总。

下一次续接仅先读取主计划、交接记录、当前批次及其必要契约，再按缺口展开。若实际代码、测试或版本与交接记录不符，先修正状态，不能依据旧记录重复报完成。

发生接口或范围调整时，在主计划登记决策及受影响批次；已经通过的相关验收重新进入待验证状态。

## 九、迁移、交付与完成标准

### 9.1 旧数据迁移

迁移分为兼容读取和显式整理两部分：

- 升级后先通过适配器读取旧对象，不批量改写业务数据。
- 旧 Research 在下次使用时采用持续探索默认策略；不在安装时为全部历史生成记忆目录。
- 旧 Run 保持原身份，按需提取结果摘要。
- 旧研究进展表、证据台账和综合文档保留。
- 从旧文档提取事件、问题或经验时，先给出迁移预览和来源对应；不能推断未记录的失败原因或确认过程。
- 对重复记录只给出候选，不静默合并正文或删除历史。
- 迁移有幂等标记、前后指纹与恢复回执。

### 9.2 Windows x64 与发布

交付形式保持“新版源码＋配套依赖包”：

- 从新版独立目录运行 `setup.cmd --target "旧工作区路径" --register --open`。
- 继续使用旧工作区目录；新旧目录不得嵌套。
- 前端附带已构建资源和指纹，使用端不需要 Node。
- Python、Qdrant、模型和 OCR 使用受控依赖包，不逐个要求用户安装。
- 新记忆目录和跨对象地图加入共享升级 fixture 的保护清单。
- 新 schema、模板、默认配置与安装 Skill 入口加入受控框架清单；用户记忆实例不进入公共包。
- 即使模型不变，也验证新表示索引的离线重建、旧索引隔离和恢复。
- 完整依赖包通过校验、离线安装、升级及接收端再次打包检查。
- 本地发布准备可以完成；公开上传须另有明确授权，且标签、源码提交和附件对应。

### 9.3 README 和使用文档

README 按用户理解顺序重新整理：

1. Research、Run、Project、知识与核心算法分别解决什么问题。
2. 四层记忆与摘要表示的区别。
3. 谁维护原始材料、业务记录、经验、地图和索引。
4. 如何开始研究、保存结果、记录失败、暂停和继续。
5. 如何发现其他研究的局部成果，并核对适用条件。
6. 如何导入已有文档、Run 和研究总结。
7. 如何确认、质疑、撤回与检查下游影响。
8. 如何配置记录深度。
9. 常用 Skill 提示词和少量 CLI 示例。
10. Windows 安装、升级、恢复、依赖包与已知边界。

开发文档另行说明契约、事务、索引和测试，不把内部实现细节堆入日常用户流程。代码注释重点解释意图、边界、单位、兼容选择和失败处理；公式使用可读 LaTeX 并定义变量。

### 9.4 最终完成标准

只有以下条件同时满足，本次开发才能标记完成：

- Research、Run、Project 共用记录机制，默认策略与用户选择正确。
- 局部结果无需先成为全局知识即可按问题发现。
- 所有重要摘要和经验可回溯到固定来源，缺口明确。
- 即时记录、阶段整理、目标演进、暂停续接与当前任务内自主推进形成闭环。
- 新能力接入既有证据检查，未产生第二套可信度体系。
- CLI、Skill 与工作台使用同一后端规则。
- 关键可靠性、检索、长任务、前端及真实升级测试通过。
- 新版源码、构建资源、依赖包、README 和验证 Run 相互对应。
- 交接档案明确实际完成项、验证范围及仍需真实业务确认的事项。

当前交付为开发与执行方案；上述代码、执行档案和测试记录在实施批次中产生，本轮不将其表述为已经完成。
