# 文档与模块影响维护

本手册规定代码演进后如何同步可读介绍。实现能力以当前 schema、代码和实际回执核对；用户规则描述应遵守的要求。两者冲突时记录具体缺口，不通过修改说明把未实现能力变成已经完成。

## 一个概念维护在哪里

| 内容 | 主要维护位置 | 其他文件如何引用 |
|---|---|---|
| 全局模块职责、运行链路、实际边界 | [ARCHITECTURE.md](../ARCHITECTURE.md) | README 概括功能后链接，不复制实现细节 |
| 对象、层级、技术单元、章节与双文稿定义 | [研究记录标准](RESEARCH_RECORDING.md) | README、MEMORY 与 Skill 只给当前任务所需短说明 |
| 机器字段、枚举、验证规则 | memory-v3 schema、contracts、领域代码 | [请求示例](MEMORY_REQUESTS.md)对应实际动作；兼容 v1/v2 明确标出 |
| Run 归属、文件登记与原始材料 | [对象保存](OBJECT_RUN_STORAGE.md)、[Run 捕获](RUN_CAPTURE.md) | 目录 README 只说明本目录接受什么 |
| 材料检索、记忆检索、关联和证据准入 | 各现行使用手册 | 区分两条产品路径、评估方案与候选设计 |
| 测试定义与实际执行 | [TESTING.md](TESTING.md)、catalog、固定 Run | 定义、执行、AI 自查、人工/科学复核分开 |
| 演进理由、时点和模块影响 | 当前开发 Project 的计划、时间线与影响图 | 根入口保留导航，固定 Run 保存每轮证据 |

本完整工作区的维护 Project 是 `PRJ-ARCHITECTURE-EVOLUTION`，现行图位于 `projects/architecture-evolution/context/MODULE_IMPACT.md`，时间盘点位于其 `docs/`。Project 实例不随公共源码包分发；使用源码包时按本手册与架构说明检查，必要时在当地工作区创建或复用自己的演进 Project。不要为让链接存在而复制另一工作区的业务记录。

## 每次开发如何检查

1. **定位变化原因。** 在当前项目影响图或架构职责表中确定本次改变的模块；写明接口、状态、内容语义、索引投影、UI 或部署中哪一项变化。
2. **沿关联找需要检查的入口。** 检查调用方、数据读取者、来源与复核、上下文组包、前端/生成类型、用户手册、README/AGENTS、Skill、测试及迁移。只沿实际关联展开，简单任务不需要通读全库。
3. **保存处置。** 在本次 Run 或小任务摘要记录“需修改 / 已检查无需修改 / 延期及理由”。已经考虑但无需改变的模块也说明判断依据；不要求每次把所有文件改一遍。
4. **更新各自的权威内容。** 先核对契约与实际实现，再改现行说明和使用示例。职责或接口变化时修订项目影响图；生成类型、资源和测试按各自既有工具维护。
5. **验证并固定时点。** 运行相应分级测试、文档链接与命令检查，结构变化后 `refresh-index` 和 `validate`。把输入指纹、影响处置、实际回执和必要图快照保存在固定 Run；失败、未执行和人工待审如实保留。

这是一项开发检查约定，不是后台监听器。程序不会自动理解任意代码变化、修正文稿或确认所有影响。若新增关系无法在现有图中表达，先补图的节点/边与理由，再决定是否需要新的自动化。

## 区分当前说明与历史记录

- 现行手册说明现在如何使用，不持续堆积“本轮/下一批”等很快过期的状态；执行状态链接到对应 Run 或状态台账。
- 历史设计保留当时的字段、目标、失败和待办，可以在顶部增加“历史时点、后续替代及现行入口”。不能批量把旧 L1、旧 schema 版本或旧验收结果替换成新术语。
- 时间线分别记录正文声明的实施日期、Git 提交/合入日期和本次核对时间。日期不明就留空；不以文件 mtime 猜测研发顺序。
- 规范记忆提交、固定 Run、原始数据、冻结快照和测试 fixture 不是普通介绍文件；文档整理不得重写这些字节或重新计算哈希掩盖变化。
- README 先解释用户目标、主要概念和操作入口；阶段历史放 Project。对已发布能力、仅评估方案、未来候选明确区分。

## 本次典型影响路径

L1 从单一实验说明演进为技术单元后，需要检查：schema/校验 → 存储兼容 → 检索表示与完整块展开 → 章节/双文稿 → 工作台和生成类型 → 研究/维护 Skill → README 与记录手册 → 固定引用、预算和迁移测试。L4 地图继续组织知识关系，独立文稿不应被重新塞回 L4 或增加为 L5。

新增详细定义集中在记录标准，其他入口保留简要定义和链接，降低下次演进时重复修改却遗漏某处的风险。
