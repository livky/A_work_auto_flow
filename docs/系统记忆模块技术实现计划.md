## 1. 技术目标

让当前协作 AI 通过统一入口，把文本、结构化内容和获准来源引用保存为可追溯记录；程序负责正确存储、版本与状态约束、检索、影响计算和视图组装。AI 负责价值判断、内容提取、总结及有依据的修订。保存成功、执行成功、科学结论已复核分别表达。

| 目标                 | 可观察的交付行为                                                                       | 对应任务 |
| -------------------- | -------------------------------------------------------------------------------------- | -------- |
| T01 统一记录         | 八类已有业务对象使用相同记忆入口，保留各自业务字段；不要求每次生成所有层级             | W01–W03 |
| T02 可靠修改         | 单对象批次原子提交，重复请求不重复写入；保留旧版本、撤回历史及可恢复回执               | W02、W04 |

### 明确边界

- 仅 L0 原始材料、L1 过程与结果、L2 有边界经验、L3 研究地图。问题、路线、检查点、关联和检索表示是辅助实体，不引入 L4。
- 跨项目指跨业务对象，不要求先创建 Project。一个记录只有一个规范归属，其他对象通过稳定 ID 和固定版本引用。
- 首版复用本地 SQLite FTS、Qdrant、现有模型及工作台栈，不引入新模型服务、图数据库或后台自主研究调度。
- AI 撰写的总结、边界和关联解释是长期内容；索引、向量、反向引用、纯显示视图可重建。
- 对话只能保存实际取得且获准的内容；用户/AI 的可核对决策说明不包含私有思维链。
- 核心算法仍需公司算法文档依据；本模块属于框架代码，不能登记为业务核心算法。
- 上一轮交付计划、合成材料及计划自检工具。2026-09-08用户已要求分工并开始实施；首批范围与分工见[实施批次](design/system-memory/IMPLEMENTATION.md)，真实进度见STATUS。最终Skill及Release仍按后续任务与授权交付。

## 3. 实施路线

1. W00 固定基线和测试材料；W01 固定契约。
2. W02 完成存储与最小 CLI，W03 完成已有对象适配。先验证“AI 提交 → 读取 → 修改 → 回执”。
3. W04 接入证据；W05 做研究状态；W06 做索引。这三项在 W03 后可分别推进，但共享契约变更必须先回到 W01。
4. W07 做关联；W08 做研究经过、查询包和续接；W09 做变化巩固与跨项目总结。
5. W10 接入工作台；W11 完成迁移；W12 在全部底层数据结构、入口与算法通过后编写调用指导与 Skill。
6. W13 汇总技术验收，并执行H01–H18常用功能验收，保存真实返回和AI实际查阅内容，整理用户审查包；用户确认后记录整体验收结果。

“可并行”描述开发依赖；本批按用户要求进行了文件边界明确的代理分工。详细拆分及每项测试 ID 见任务文档。

## 4. 验收原则

每个测试点都有唯一 ID、固定场景、操作、预期结果和证据清单。所有必需断言满足才算 passed；必要测试 skipped、未运行、结果不确定均不得算通过。

测试分为四类：

- **确定性程序检查**：字段、状态、版本、去重、权限、恢复、导出完整性。
- **检索评价**：固定开发/留出查询、规范 ID 相关性标注、消融比较及量化门槛。
- **AI 场景评价**：给固定材料，让 AI 调用真实接口，再只凭落盘内容续接；按可核对事实和操作结果评分，不要求固定措辞。
- **人类可阅使用验收**：AI通过Skill或正式产品完成日常任务，原样留存实际返回及真正查阅的内容；先给AI自评，再由用户审查确认。命令成功、文件已下载或AI声称通过均不能代替实际查阅和用户审查。

新增H01–H18的清单和记录模板独立放在human-acceptance目录，作为W13增补；不改原115点冻结配方。每项需真实操作完成、证据齐全、预期符合且用户明确确认，才算最终通过。无需用户逐步批准测试操作，AI先完成已授权场景再集中提交审查。

本轮的计划自检只证明材料引用与测试覆盖清单自洽，不证明未来接口已实现、测试已通过或经验具有业务有效性。
