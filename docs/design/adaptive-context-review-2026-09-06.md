# 分阶段上下文与工作区一致性审查

本记录是 2026-09-06 的后续实现阶段，覆盖当前工作区维护的规则、入口、手册、模板、工作流、检索/CLI 与测试。根目录规则和用户最新要求优先；以前的设计/审查是历史记录，不当成现行机制。第三方运行时通过已安装版本、校验清单和集成行为检查，不逐行改写第三方库。原始研究证据和业务原件未修改。

## 问题与修正

| 发现 | 已处理 |
|---|---|
| 一命中就全文，难判断代码/Run 是否必要 | 独立 context_engine：算法基线优先，其他来源按角色、阶段、长度和预算选择 |
| 可能因先读文档而漏掉实现差异 | 每个目标模块优先保留一份相关核心实现，mismatch 优先核对；不预设哪方正确 |
| 模块名出现在路径中导致应用文件误加入 | 应用/项目首轮需正文命中、明确冲突或用户指定，不把路径命中当必要证据 |
| 长代码/Run 占满上下文 | Python 按函数边界读取；长 Run 首轮字段摘录；预算不足与不完整状态显式记录 |
| 用户选择和反复失败没有调查链 | CTX/CF 记录阶段、父子关系、反馈原因、来源指纹、偏好与选择；未解决/冲突最多自动扩展两次 |
| 候选清单本身可能过长 | 预览最多 40 项，全部清单保存到独立文件和调查记录 |
| 旧向量命中策略与新角色策略冲突 | 当前 CLI 使用角色策略；配置移除 vector_context_mode；保留基础装载函数作为程序接口 |
| 关键词存在于文件但利用不统一 | 模块 aliases、Run keywords、sources keywords 接入 FTS 加权字段及限长嵌入前缀；不伪称自动语义提词 |
| Skill 只存在方法源，不能直接发现 | 安装两个常用轻量入口，已被当前会话识别；方法正文只维护一份 |
| 旧手册/局部规则与根目录不一致 | 更新 README、ARCHITECTURE、START_HERE/NOW、材料/检索手册、模块/Run/研究/工具规则及工作流；修正强制人工评审和固定重复次数等机械约束 |
| 测试固定工作流总数 | 改为验证必需入口与所有工作流格式，不限制合理扩展 |

## 能力边界

分阶段策略是可解释的初版启发式，不是经过训练的必要性判断器。AI/用户提出证据缺口，程序据反馈扩展；未知问题不会自行得到正确性判定。真实问题评估集为空，当前测试不证明公司资料库召回质量。

普通文件保存不会触发向量化，维护流程在写回后调用 index-knowledge，查询也刷新。刷新仍需遍历获准目录和读取哈希；Qdrant Python local 计算本地向量相似度，未把它宣传为服务器 HNSW 索引。后续大规模数据性能需独立验收。
