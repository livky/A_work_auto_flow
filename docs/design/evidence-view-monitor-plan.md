用户要求：先让证据为什么保存、依据、复核、失效及报告影响可见，再增加材料变化、实验完成和依赖失效的只读监测。自动整理只提出候选，重复出现或被引用不能提升可信状态。

## 范围与设计

- 复用 evidence.py；本地网页提供搜索、状态筛选、结论/对象详情、证据定位、复核历史与已登记的下游报告。无外部资源、无编辑/复核按钮，不依赖向量或 OCR。
- 只读服务仅监听 127.0.0.1，按固定路由输出页面和结构化数据，不开放工作区文件服务器。同时支持离线 HTML 快照，明确生成时间。
- 监测仅扫描既有检索目录和逐文件授权来源，加上已登记证据引用；记录新增/修改/移出范围、Run 终态变化、依赖风险变化。首次只建基线，不把历史实验误报为刚完成。
- 监测状态保存于独立本机文件；原子写入、串行锁、失败不覆盖基线；观察时间与真实失效时间分开。不进行索引重建、实验执行、合并或状态晋升。
- 完全相同的结论或材料仅作为重复候选；维护候选可追溯到触发版本，失效/恢复不等于自动复核。
- 定时运行频率按用户选择；不启动无管理的系统常驻任务。
