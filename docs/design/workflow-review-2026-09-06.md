结论：保留文件化证据、复核、检索和连接边界，减少常驻流程指令。先补现有机制缺口，再考虑更复杂平台。

## 修改前的发现

| 级别 | 实际问题与证据 | 本次处理 |
|---|---|---|
| P1 | `refresh_index` 没有 Run 数据源，无法按既有导航找历史分析 | 新增 Run 索引和即时 search-runs，近期导航限 20 项 |
| P1 | create_run 只有可覆盖的 review 字段，没有撤回历史或影响计算 | 新增 review-run，追加前后状态，传播已登记 parent_run_ids 的待复核信号 |
| P2 | `slugify(title)` 拒绝纯中文 Run 标题，README 示例不能运行 | 标题与 UUID 后缀 ID 分离，允许中文并避免同秒同名碰撞 |
| P2 | 根规则要求任务固定路由和多种检查，项目模板在首次启用前要求填齐所有 TBD | 根规则精简，详细检查移到参考文档；按当前任务完善模板 |
| P2 | README 按目录宣称是否为“正式事实源”，混淆存储位置与可信度 | 按记录、执行、复核分别说明，增加自然语言使用场景 |

## 对五个问题的回答

1. **应该精简。** 优先减少重复指令、固定步骤、与任务无关的模板要求，不必搬空所有目录。领域方法留作按需参考，安全约束和证据责任仍保留。后续使用真实任务检验规则是否造成额外停顿，不按模型名称武断删除所有技能。
2. **默认记忆不足以作为正式证据库。** 模型上下文、客户端记忆、项目持久记录分工不同。官方说明本地记忆默认关闭且后台延迟更新，关键规则应放文档。本机配置文件的定向检查未发现显式 memories 开关，但这不能确定应用/托管层实际启用状态；本次未改设置。[官方记忆文档](https://learn.chatgpt.com/docs/customization/memories?surface=app)
3. **此前只要求正式分析建立 Run，并没有关键词字段或 Run 索引实现。** 本次补齐。每条命令不必独立建 Run；同一问题步骤汇总，独立输入结果和正式依据留独立记录。关键词由 AI 写入，代码做确定性检索；不是自动语义提取服务。
4. **确认可被修正。** 过去有 ADR superseded 与事故复盘的文字要求，但 Run 缺少明确机制。现在保留历史复核并追加质疑/撤回/替代，检索显示下游风险。确认是带范围的证据判断，不是永恒事实。真实新证据高于陈旧确认标签。
5. **用户不用手工创建 project，也不用逐条批准存档。** AI 按用户任务创建或复用项目，自动保存记录；用户负责必要业务判断，或授权明确验证流程。README 已增加开工、检索、确认、撤回和交接示例，并区分目录项目与 Codex 应用项目。

Astra 官方指南指出冲突/含糊技能指令可能引发停顿，应明确用户指令优先、按任务校准测试。这是减少指令摩擦的依据，并非取消可靠性要求。[官方模型指南](https://developers.openai.com/api/docs/guides/latest-model)

## 已有能力、此次新增和仍需人工的部分

- 已有：创建项目/研究/Run、有限导航上下文、JSON/链接等结构检查、数据边界和工具注册入口。
- 新增：Run 关键词及检索、完整派生 JSON 索引、有限近期导航、复核历史、疑点/撤回/替代状态、跨项目多级依赖影响提示。
- 由 AI 在任务中完成：写摘要与关键词、补实际运行参数和证据、维护知识卡、检索报告等引用。没有后台守护进程。
- 需人或已授权流程作准：业务真实性、适用域、关键结论复核；保存候选不需人工确认。
- 未实现：所有对象统一状态机、完整数据/报告血缘自动传播、全文/向量服务、签名审批、多写者锁、后台捕获、远程备份。即时检索仍线性扫描约定位置的 manifest，大规模时按性能实测演进。
- `build-context --task` 只是带任务说明的导航快照，不能声称它已按语义找到证据。检索命中后回源检查。

## 兼容性与恢复

现有目录/对象 ID 不迁移；旧 Run 缺少新增字段时仍可检索。复核事件在同一 JSON 内原子写入，执行状态和结论正文不改；并发复核需串行协调。派生索引可删除重建，但正式原记录不能当缓存清理。

原根规则曾保存在 [工程检查参考](workspace-rules-reference.md)，后续可读性审查将其精简为按需检查链接，不再保存完整旧规则正文。修改前的相关文件另有本机临时 ZIP 快照，位置在本次任务输出；该快照不是长期备份。正式使用前仍需落实获批版本控制和备份。

验证结果与完成进度见根目录 [PLAN.md](../../PLAN.md)。本次审查结论基于代码和文档检查，没有冒充用户已确认的业务事实。
