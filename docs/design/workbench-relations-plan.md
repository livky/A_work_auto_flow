# 工作台重构与材料关联功能开发计划

用户已确认，2026-09-07。本文件保存完整实施约定；进度单独追加，不以摘要替代计划。

## 1. 目标与架构

将当前工作台重构为可持续扩展的应用，完整实现问题辐射、主题聚合、证据链、语义相似、自动聚类、桥接候选及 AI 关系摘要。按下述步骤分别开发、验证，最终统一交付。

已确认的约束：

- 面向约 1 万份材料，采用全局聚合、局部展开。
- 前端在开发阶段构建，发布预构建资源；使用机台不需要 Node，继续通过 setup.cmd、rdwork 使用。
- 相似性与聚类按需计算、缓存结果；材料变化后提示过期。
- AI 分析复用当前会话，工作台不增加模型账号或凭据管理。
- 图中允许调整展示和保存候选；正式证据关系继续走现有记录与复核流程。

技术方案：

- 前端采用 React＋TypeScript＋Vite，构建为本地静态资源；使用相对资源地址适配现有随机访问路径。
- 图展示采用 Cytoscape.js；自动社区聚类使用 Graphology Louvain，在 Web Worker 中执行。
- 后端保留 Python 和已有业务实现，拆分 HTTP 接口、应用服务、材料适配器、任务管理和缓存。使用并发 HTTP 服务承接快速请求，耗时工作进入受控任务队列。
- 不新增图数据库，不迁移原始业务材料，不改写现有证据关系的含义。

当前重点重构入口：

| 当前代码 | 重构方向 |
|---|---|
| automation/ui/workbench.html | 拆分应用外壳、页面、公共组件、API 客户端和页面状态 |
| automation/scripts/evidence_view.py | 分离路由、来源预览、静态资源和证据服务，保留兼容入口 |
| automation/scripts/workbench.py | 保留启动入口，将监测、能力检查和新计算接入统一任务管理 |

## 2. 分步开发与交付

### 第一步：建立开发、构建和分发基础

- 建立独立前端工程，配置 TypeScript 严格检查、格式检查、Vitest、组件测试和 Playwright 浏览器测试。
- 分为应用外壳、功能页面、共享组件、API 契约和计算 Worker；功能模块通过静态注册接入导航，不引入动态插件加载。
- 建立版本化 JSON Schema 契约，开发时生成 TypeScript 类型；Python 接口测试验证输出符合契约。
- 构建产物携带资源清单、内容指纹及对应源码指纹。源码、锁文件和预构建资源进入发布版本；依赖目录和开发缓存排除。
- 修改升级和离线打包逻辑：按受控清单包含 JS、CSS、Worker、字体及许可文件，避免当前扩展名白名单漏文件。
- 构建资源缺失或版本不匹配时明确报错，不在使用机台临时下载依赖或构建。

完成标准：GitHub ZIP 解压后，无 Node 环境也能通过原命令打开新应用外壳；升级和恢复包含完整前端资源。

### 第二步：迁移现有工作台并建立服务边界

- 将首页、证据详情、来源预览、监测记录、模块导航和环境检查迁移到统一应用。
- 统一搜索、筛选、空状态、错误提示、详情侧栏及执行状态展示；保留已有功能和合成沙盒标识。
- 新接口使用 /api/v1/；现有接口、evidence-view --serve 和离线证据快照继续兼容。
- 静态资源仅由清单允许的路径提供。保留回环监听、随机路径、Host/Origin 检查，生产页面不加载 CDN 或执行材料中的脚本。
- 引入固定类型的后台任务：状态查询、进度、取消和失败原因。向量操作按工作区串行，浏览器查询不被耗时计算阻塞。
- 任务取消在安全批次边界生效；进程退出后，未完成任务标记为中断，不自动重新执行。
- 缓存结果与任务状态分别保存，失败不得覆盖最后一次完整结果。

完成标准：现有工作台功能回归通过；执行检查或图分析期间，导航和任务状态查询正常响应。

### 第三步：建立可重建的材料关系投影

- 从现有对象元数据、来源登记、Markdown 链接、Run 输入产物和证据旁文件构建统一只读投影。
- 覆盖算法、研究、Run、结论、知识、报告、项目、工具、数据卡、普通材料及可定位片段。
- 优先使用已有稳定 ID；普通文件使用工作区相对路径或已登记来源身份。重名不合并，内容相同仅提示重复候选。
- 显式区分支持、输入、背景、反证、引用、归属、产物和派生影响路径；保留原始字段、方向、定位和指纹。
- 不直接将现有检索邻接集合当成展示图。同主题材料通过主体归属组织，避免组内两两连线。
- 投影记录读取范围、缺失项、排除项、缓存时间和过期状态。读取失败显示“未知或不可读”，不能伪装成没有关联。
- 派生缓存、视图偏好和候选放在独立的本机工作台目录，排除 Git、离线包和正式检索；清除派生缓存不删除候选记录。

完成标准：每条显式关系能够回到原始记录；重建投影前后业务文件指纹不变，合成与正式材料保持隔离。

### 第四步：完成三种关系视图

- 问题辐射：以问题或材料为中心，按模型、实现、实验、反证及交付分区；默认一跳，支持两跳、重新聚焦和返回。
- 主题聚合：按已有算法、研究和项目折叠成块；保留多重归属，展开组内成员和跨主题联系。
- 证据链：查看来源、实验、结论和报告的上下游关系，同时显示版本变化、执行状态和复核状态。
- 共用搜索、关系类型筛选、节点详情、连线说明、来源预览、缩放、拖动、固定位置和布局重置。
- 支持自定义视觉分组；分组名称、成员和位置只属于视图，不创建业务算法或改变目录。
- 默认画面上限为 300 个节点、1,000 条边；超出时折叠、分页或继续展开，并显示遗漏数量。
- 实线与虚线区分记录关系和候选；颜色表示类别，风险通过独立徽标和文字表达。连接数不作为可信度。

完成标准：用户能够围绕一个问题找到直接依据、反证和下游报告，并从任意连线解释“为什么相连”。

### 第五步：完成相似性、自动聚类和桥接候选

- 关键词候选使用现有业务关键词及别名，展示具体共享词；不将机械分词冒充业务关键词。
- 语义候选复用当前本地嵌入模型和已有片段向量。新增只读查询通道，缺少索引时提示用户更新，不在打开图时自动重建。
- 每次选择最多 50 个种子材料，在当前允许范围内检索近邻；每个种子默认展示前 10 份候选，保留匹配片段、模型身份和原始相似度。
- 长材料按确定性的分段采样处理，并列出未覆盖片段；不将部分采样结果描述为全文比较。
- 不计算全库两两相似度。全局视图可以使用已完成的候选缓存，明确语义分析覆盖范围。
- Louvain 聚类针对当前选定范围内的稀疏关系运行；排除导航枢纽和纯归属边，固定随机种子及参数。显式关系聚类与语义候选聚类作为独立模式。
- 聚类默认以已有关键词命名；AI 可通过当前会话提供名称与解释，界面标明其来源。
- 桥接功能展示跨簇材料及待研究的主题组合，生成带依据的待核对问题，不自动声明因果关系或真实知识缺口。
- 模型缺失时显式关系图、关键词候选和结构聚类仍可使用；语义功能明确显示不可用。

完成标准：所有候选都能说明计算依据；相似、反证和正式支持可以同时存在，不发生可信状态自动提升。

### 第六步：接入 AI 关系摘要与候选记录

- 工作台支持复制 Markdown、导出 JSON，将当前选择的局部关系交给 AI。
- 摘要包含问题、中心对象、关系类型和方向、定位、指纹、复核状态、候选依据，以及未读、排除和超限信息；默认不导出全部正文。
- 增加与现有 CLI 风格一致的 relations 命令组，提供查看、分析、导出、候选导入和候选处理。
- 网页与 CLI 共用同一服务，不要求 AI 先打开浏览器才能获得关系。
- 更新现有工作区技能：先读取关系摘要定位缺口，再用已有上下文命令装载必要原文，保持预算和用户排除项。
- AI 回传的主题名称、关联解释和桥接问题必须引用源 ID、定位及生成时指纹；输入版本改变时标为过期。
- 候选可以保存、驳回或标记为已处理，保留处理历史；“已处理”不等于证据已复核。
- 需要形成正式业务记录时，通过现有研究、Run 和证据命令登记，禁止将展示关系类型直接塞入正式依赖字段。

完成标准：AI 能利用同一局部关系解释调查路径，定位上游变化和反证；整个过程不依赖新的云模型连接。

## 3. 接口与状态约定

| 接口组 | 能力 |
|---|---|
| 能力与版本 | 返回 API 版本、前端构建身份及可用功能 |
| 材料与关系 | 搜索、局部子图、主题成员、关系详情及授权来源预览 |
| 分析任务 | 提交固定类型分析、查询进度、取消及读取结果 |
| 视图与候选 | 保存展示偏好、关联建议及处理历史 |
| 关系导出 | 输出与当前范围一致的 Markdown/JSON 摘要 |

关键约定：

- 读取接口不修改业务记录；分析操作只写本机任务、缓存和候选。
- 节点使用稳定身份，边同时保存原始方向与展示方向；归属关系和影响路径不冒充原文证据。
- 原始记录状态、派生结果状态和任务执行状态分别表示。
- 任务队列串行使用 Qdrant；与独立 CLI 冲突时返回明确的忙碌状态，不并发打开同一存储或清除其锁。
- 浏览器路由采用随机服务前缀下的 hash 路由，静态资源使用相对地址；API 版本不兼容时提示刷新或升级。
- 不增加常驻系统服务、开机任务、自动模型调用或新的永久环境变量。

## 4. 验证与最终验收

- 关系正确性：方向、多重归属、普通引用、反证、循环、缺失来源、重名及重复内容；候选不参与正式失效传播。
- 状态与版本：输入变更、缓存过期、AI 回传过期、取消、中断、失败保留旧结果，以及业务文件不被展示操作修改。
- 界面与 AI：三种视图切换、折叠与选择保持、连线回源、中文路径、键盘操作、关系摘要和页面范围一致。
- 语义与聚类：确定性固定数据测试加真实本地模型集成测试；覆盖相似但矛盾、无候选、长材料采样和模型缺失，不写死模型分数。
- 性能：使用本机生成的 1 万材料、10 万稀疏关系夹具；缓存可用后局部视图目标 3 秒内可操作，分析期间轻量状态接口目标 500 毫秒内响应，记录验收硬件与测量方式。
- 迁移：Windows 中文及空格路径，无 Node 机台启动，旧数据与配置保留，资源完整分发，重复升级和冲突恢复。
- 交付门槛：Python 回归、前端类型检查、组件测试、构建和浏览器端到端测试通过；完整配置验证不得用跳过真实模型测试代替成功。

所有示例和性能夹具由生成器本机创建，不提交数据实例。软件验收与真实研发问题的有效性评价分别记录。
