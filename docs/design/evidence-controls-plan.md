## 数据与接口设计

- 在 Run、研究、算法元数据中增加可选 claims/dependencies；普通知识和报告使用逐文档 `.evidence.json` 旁文件，不复制原文。
- 结论保存 ID、类型、正文、scope、证据引用、复核及历史。依赖关系分 supports/input/background/contradicts；只有前两类传播失效。
- 证据引用固定 target、sha256 和 locator；文件依据只允许工作区内或已逐文件登记的来源。对象指纹排除复核历史等动态记录，复核变化仍通过状态传播。
- 正式检查拒绝不完整、未复核、错 scope、版本变化、失效或循环依赖。探索模式显示风险；正式上下文只导出合格的结论条目，避免原文中未复核内容混入。
- 新增 doctor、verify、evidence-status、review-claim、check-run/finalize-run 等 CLI 入口；检查失败使用非零退出码。finalize 只证明记录完整与检查通过，不自动作科学复核。

## 验证与限制

使用合成隔离数据验证机制，不创建虚构公司算法卡或业务评估标签。现有真实评估集保持为空，待首批获准材料接入。缺本地模型和依赖应清晰报缺失，不自动下载或改变原检索配置。当前宿主与 OS 的访问控制不在本轮重建；新 CLI 也不宣称能阻止任意外部编辑器修改文件。

完成条件：新入口可复用、失败路径有测试、历史记录仍可检索、正式使用能阻止失效结论；全量回归、健康状态和结构校验准确记录。
