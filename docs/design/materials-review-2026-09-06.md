## 发现与处理

| 问题 | 处理 |
|---|---|
| README 场景重复，概念分散，能力边界难查 | 改为概念、目录分工、提示词、能力表和操作入口；具体流程集中到材料手册 |
| 大量材料缺少可恢复阅读进度及融合约定 | 增加批次清单、阅读范围、关键词/别名、去重引用、版本链、冲突保留和检索抽查 |
| 模块卡缺少文档与代码分别版本化的对应关系 | 补多对多映射、符号、指纹、检查状态和影响记录；在 START_HERE 加问答检索路由 |
| 研究模板指向研究 runs，但 CLI 只检索项目 Run | 改为项目保存 Run、研究引用；旧占位目录可放引用说明，避免另建未检索证据库 |
| 保留策略写自动清理，与根规则不一致 | 改为按策略及已有授权清理，明确当前无自动删除任务 |
| tools/scripts 禁止尚未重复验证的新工具，与用户入口冲突 | 允许直接创建通用工具并登记开发/验证状态 |
| 报告说明只允许批准证据，与草稿规则不一致 | 允许明确标注限制的未复核草稿，发布仍遵循既有边界 |
| 旧根规则副本重复且保留固定流程/全局事实等级 | 精简为领域检查链接，取消重复规则；历史审查仍保留 |
| 项目/研究标题含引号、反斜线或换行会破坏 JSON；替换还可能改写标题中的模板字面量 | JSON 转义并单次替换，测试原文保真 |
| 索引遇到 JSON 数组等非对象会 traceback | 返回明确警告，保留其他可索引对象 |
| reports/generated 排除项按单个路径组件比较，实际上不生效 | 增加路径前缀判断并测试 |
| 尖括号包裹的 Markdown 路径直接跳过校验 | 正确解包并检查带空格路径，增加测试 |

## 验证与限制

- 14 项单元测试通过，覆盖新增回归及原有创建、检索、撤回、依赖传播、工作流元数据检查。
- 维护工作流沿用现有 context-maintenance，增加导入/变更模式，保持五个工作流源，未增加重复技能。
- 官方 quick_validate.py 尝试运行，但解释器缺 PyYAML，未完成该校验；现有测试检查全部源的基本 frontmatter、名称和描述，引用由 workspace validate 检查。
- 尚无实际算法或材料可用于召回质量测试；批量导入、提词、版本对比与相关材料加载是 AI 工作约定，不是新增解析或语义检索引擎。
- 没有文件监听、自动映射失效、自动报告更新、完整 schema 校验或备份；已有 Run 依赖提示仅覆盖登记关系。
- 修改前临时副本与最终检查结果记录在根 PLAN 的当前续作段。
