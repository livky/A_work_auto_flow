# 测试点与明确验收标准

版本1.0，共115个测试点。机器真源为[acceptance.json](fixtures/acceptance.json)，本文是同版阅读视图。**当前全部为not-run产品验收规格。**

版本1.1增补：保留本文技术测试，另加[18个人类可阅的整体评价与交付核对测试点](05-human-acceptance.md)。它们使用日常任务描述，要求AI通过Skill/正式产品取得真实结果、实际查阅并保存内容，最后由用户审查。整体计划现为115个技术测试＋18个使用验收，共133项；新增清单独立版本保存，不改原冻结配方。

## 执行约定

- 每例使用独立临时工作区，输入见[合成材料说明](fixtures/README.md)。负例是配方内修改，不在真实业务目录制造损坏。
- 前置状态固定：时钟、ID、原件内容、配置。每例执行前保存HEAD、规范ID/revision、受保护文件SHA-256和目录集合。
- 除步骤明确的新修订、状态事件或故障注入外，旧修订、原始材料、无关对象的字节指纹全部不变。
- 所有验收条目必须有断言/证据；退出码0不能单独证明成功，报错也须检查无意外写入。
- 逐例结果字段：test_id、status、code_commit、dirty_diff_hash、fixture_manifest_hash、environment、command/request、started_at、ended_at、assertions、artifacts、limitations。
- status取passed/failed/not-run/skipped；产品代码未实现不能用计划自检替代。文件IO/数学单元测试可注入故障和固定向量，Windows占用、setup、浏览器、模型保持真实集成。
- 正反例混合的测试按参数逐一记录；缺任一变体不得整项passed。

## 检索与质量指标

同一记录多个表示先按规范ID折叠。相关标签grade≥1；Recall@6为前6名相关ID数除该查询相关ID总数。nDCG@6使用增益2^grade−1、折扣log2(rank+1)，除以同查询理想DCG。按查询宏平均。

48条查询都有相关标签，开发32条、留出16条。零结果记Recall=0；另外的无相关问题测正确空结果，不混入上述平均。I08规定真实模型指标；不得在见到留出结果后继续用该留出集调参并称独立验收。

边界丢失率只针对已装载条目：遗漏其适用或禁用信息计一次；整体省略且登记原因不计丢失，仍影响召回/可用性。权限越界、错误正式引用、独立证据重复计数必须为零，不能被平均相关性分数抵消。

错误类比按G04和K组标注检查；允许提出待核对候选，但禁止把错误候选当科学支持或无条件建议输出。AI评价按事实/引用/边界/操作结果，允许不同措辞。
