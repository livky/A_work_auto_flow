版本1.1；归属W13。本组在原有115个技术测试点上，增加18个日常使用验收点H01–H18。当前只是验收计划，未执行真实产品操作，未产生实际使用结果。

**本组要回答：AI像日常工作一样使用Skill或正式产品，能否得到预期结果，并把实际看过的内容完整留给用户审查。**

## 1. 用户如何阅读这份验收

每项只需看五件事：

1. 我让AI做了什么。
2. 产品实际返回了什么。
3. AI真正打开和读到了什么。
4. 得到的结果是否符合这项任务的预期。
5. 我是否认可这次结果，或还需要补什么证据。

无需用户理解数据库表、函数名或内部错误码。技术测试保持原样，作为程序可靠性的依据；本组补上真实使用和可读结果的审查。

## 2. 统一执行方式

每个场景遵循：**给出日常任务 → AI通过正式入口操作 → 保存真实返回 → AI实际查阅结果 → 逐项对照预期 → 形成审查页 → 用户确认。**

- 可使用正式Skill，也可直接操作已实现的CLI、API或工作台。每项选择适用入口，不要求所有场景重复跑全部入口；必须记录实际采用的入口、产品版本和Skill版本。
- Skill必须真正调用产品并取得返回。只读Skill文字、调用内部函数、使用mock返回或自行编写“看起来正确”的结果不能通过本组。
- H15必须实际操作工作台；不能只调用后端接口就声称界面可用。H11须使用新的AI会话或隔离上下文，保留第二轮实际获得的输入。
- 使用已有合成材料的独立副本。可以在一次研究旅程里连续执行，但记录每项开始时的已有内容及前序用例；依赖前项失败时标受阻，不能跳过失败伪造后续成功。
- 复用K组/Z组已有真实执行证据可以减少重复操作，前提是产品版本、输入和本组必需查阅记录完整匹配；缺少实际返回/查阅记录就补做。
- 提前固定预期。不要在看到实际结果后修改预期来使它通过。允许不同表述，只要事实、来源、边界和功能效果满足预期。
- 若产品/Skill尚未实现或实际入口不可用，记“未执行/受阻”。本轮仅增补计划，不能把文档自检当作这些使用场景已经完成。

## 3. 必须留下的查阅证据

**保存文件不等于AI已经读过，AI概述也不能代替产品真实返回。**

| 留存内容 | 用户能核对什么 |
|---|---|
| 原始任务与执行前预期 | 当时到底要求产品完成什么 |
| 实际入口与调用 | 使用了哪个Skill/产品功能，提交了什么范围和参数 |
| 产品实际返回原文 | 原样保留JSON、Markdown、工具消息、错误和重试；表格可展示，但不能只留“成功”摘要 |
| AI实际查阅的内容 | 原样保存AI读到的文本、具体页面/段落及读取时间；图形页面保存实际截图和对应阅读说明 |
| 实际产物与重新打开结果 | 保存、导出、修改后重新读取，证明内容确实落盘且可再取得 |
| 预期与实际对照 | 每个预期点对应观察事实、证据位置及AI自评 |
| 用户审查记录 | 用户明确选择通过/不通过/补证据，附意见与日期；AI不得代填通过 |

若返回被截断，记录截断位置以及是否继续展开；未读取部分明确“未读”，不能推断其内容。多页结果逐页留存，保留分页范围和遗漏；不为凑“完整”声称读过所有来源。

如果返回本身就是摘要，记录“读到摘要”，需要验证来源时再实际打开原件。截图必须是实际访问时的画面；不能用模拟图片替代。文字抽取只辅助阅读，不改写原始返回。

查阅记录保存可核对的事实、引用和结论说明，不保存AI私有思维链。用户审查是本轮产品验收判断，不自动把业务结论改为accepted。

## 4. 什么情况算通过

| 情况 | 记录方式 |
|---|---|
| 尚未实际使用功能 | 未执行 |
| 功能/资料缺失，无法继续 | 受阻，说明缺什么 |
| 已操作，但结果不符或证据不完整 | AI自评“不符预期/暂不能判断”，等待修复或补证据 |
| 实际结果逐项符合预期，查阅证据齐全 | AI自评“符合预期”，提交用户审查 |
| 用户审查确认符合预期 | 该项最终通过 |
| 用户认为结果不符或需要补充 | 不通过或待补证据，保留原记录和反馈 |

**最终通过条件：真实操作完成＋实际返回与查阅证据齐全＋各预期符合＋用户明确确认。**

出错后允许修复重测，每次保留独立尝试和关联，不能覆盖旧失败。用户不需要在每次操作前批准，AI应先自主完成已授权的合成场景、整理审查包，再由用户集中审查。

18项全部确认后，才标“人类可阅整体验收通过”。技术测试未完成时，不能仅凭本组通过宣布整个开发完成；反之，技术测试全通过但本组仍待审查，也不能宣布使用体验已获确认。

### H01 开始一项研究并保存材料

**给AI的任务：** “把这份预热材料留到当前研究里，说明来源和还不知道的地方。”

**AI应实际完成：**

1. AI选用当前研究或按正式入口建立研究，通过Skill/产品登记给定来源。
2. 保存后重新查询并打开该记录，查阅来源定位和原文。

**用户看到以下结果即可判断是否符合预期：**

- 能找到刚保存的材料，归属清楚，正文与输入一致。
- 原文仍在原位置；未取得的信息明确写出，没有凭空补齐。

**这一项必须附上：** 保存回执；重新查询返回；实际打开的材料与来源定位。

**当前：** 未执行；AI尚未评价；等待实际结果后提交用户审查。

### H02 保存一次分析，之后能查明做了什么

**给AI的任务：** “把这次合成分析的输入、配置、结果和限制保存下来，随后告诉我如何复查。”

2. 重新读取分析详情，打开输入和结果，核对数值与适用条件。

**用户看到以下结果即可判断是否符合预期：**

- 能够读到样本A、预热30分钟、20–25℃、合成偏差0.2及适用限制。
- 同一次分析只有一个Run身份；保存或执行成功没有被说成结论已经复核。

**这一项必须附上：** 实际保存的Run详情；输入/结果的查阅内容；AI给出的复查说明。

**当前：** 未执行；AI尚未评价；等待实际结果后提交用户审查。

### H03 失败也能留下有用的边界

**给AI的任务：** “配置S1没能区分X和Y，请保留这次失败，说明下次什么条件下值得重试。”

**AI应实际完成：**

1. AI保存失败经过、测试条件、不能推出的结论和再试条件。
2. 随后按问题检索失败记录，实际打开结果查阅。

**用户看到以下结果即可判断是否符合预期：**

- 能找回S1与X/Y的具体限制，以及检查S2的下一步。
- 没有把一次失败扩大成所有方法都无效，也没有只保留成功经验。

**这一项必须附上：** 失败保存与检索返回；失败正文和再试条件；AI复述的适用边界。

### H12 纠正旧结论后，不再把错误依据当成当前答案

**给AI的任务：** “新材料与原来的0.2结果冲突，请保存这件事、检查影响，并按本次测试给定的复核依据将旧结论撤回。”

**AI应实际完成：**

1. AI读取固定的thermal-v2冲突材料，保存新证据与对比。
2. 通过正式复核入口执行本合成场景已授权的撤回，取得影响清单。
3. 重新检索并打开受影响总结和报告入口，查阅它们现在如何提示风险。

**用户看到以下结果即可判断是否符合预期：**

## 7. 实施人员附录：记录格式与保存位置

- [用例清单](human-acceptance/cases.json)：18项任务、动作、预期和必需附件。
- [W13增补清单](human-acceptance/plan-extension.json)：在115个技术测试基础上追加18项；总计133项，不改原冻结数据。
- [结果记录模板](human-acceptance/result-template.json)：分开保存执行状态、AI自评和用户审查。
- [单次查阅记录模板](human-acceptance/read-event-template.json)：关联call_id、实际返回、AI读到的内容和定位。
- 既有场景/材料见[合成材料说明](fixtures/README.md)。H用例与技术测试的对应ID保留在cases.json，用户无需逐一理解这些ID。

每次实际验收建固定Run，建议将整体审查页、逐项结果、调用原文、查阅正文/截图和产物放在该Run的human-acceptance目录。相对路径、SHA-256、对象版本和读取时间共同固定证据；唯一一份长期审查材料不能只放缓存或聊天里。

推荐文件布局仅供实施，不在本轮预填虚构结果：

```text
<实际验收Run>/human-acceptance/
  REVIEW.md
  H01/attempt-001/
    RESULT.md
    result.json
    calls.jsonl
    read-log.jsonl
    returns/
    read-content/
    artifacts/
    user-review.json
```

read-log每次查阅追加一条，不将下载动作等同read。calls/returns保存真实调用与完整可取得返回；read-content保存AI真正收到的文字/截图，标记完整/部分/未读。多个相同内容附件可共享同一固定文件，但引用必须能解析。

每次重测使用新的attempt目录并关联上次尝试。user-review保留用户原意见/出处、审查日期和结果；没有用户意见时保持pending。产品功能返回敏感内容时沿已有授权保存，本组默认用合成材料，不额外扩大读取范围。
