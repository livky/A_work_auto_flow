本轮根据用户对“研究经过”拼凑感的反馈实施。上一版虽然保留了 L1–L4 正文，却直接按存储层级拼成页面，并在正文前后再次显示结构化字段，产生重复、缺少衔接和层级导航抢占阅读顺序。目标是读者无需理解记忆系统也能阅读一份完整技术报告。

## 技术目标

1. 按研究论证组织：问题与范围 → 共同方法 → 按因果/实验顺序展开的详细实验 → 讨论 → 结论与后续工作。没有适用内容的章节可以省略，不能为模板编造实验。
2. 实验事实先展开，跨实验经验与综合结论随后出现。L0–L4 是存储职责，不是报告目录；默认正文不显示层级卡片、字段清单和事务元数据。
3. AI 明确说明上一轮发现为何引出下一轮。连接关系集中编写和审阅，不向每条记录增加脱离上下文的“过渡语”。
4. 完整保留公式、关键参数、中间计算、图表和限制。各段依据可追溯到固定修订，旧引用、权限、撤回和缺失来源保护不能因重新排版而失效。
5. 原始实验不重跑；本轮重新整理浮点求和的 L1 与报告编排。使用新修订保留旧记录，AI 审核后交由用户人工审阅。

## 技术落地

### 1. 集中编排、按引用组装

在 v2 `map` 的 payload 中增加可选 `report`，作为 L4 对研究整体的写作安排，不新增层级或独立数据库。旧 v1/v2 记录继续可读，已有 content_hash 算法不改。

`report` 包含 `version: 1`、报告 `title` 和显式有序 `sections`。每节包含稳定 `section_id`、`title`、`role` 以及有序 `blocks`。role 为 introduction / methods / experiment / discussion / conclusion / appendix。

两种正文块：

- prose：`type: "prose"`、`markdown`、`evidence_refs`。AI 写背景、共同方法、实验衔接、讨论和结论，引用 L1/L2/L3 或固定原始依据。没有事实主张的引言可为空引用。
- detail：`type: "detail"`、`ref`。固定到 L1 detail 的 record ID、revision、SHA-256，直接展示该版本的正文。正文必须已经包含必要参数、公式、表格、图示与限制；不再把 payload 中的同一信息机械加在正文前后。

共享方法在报告中定义一次；每轮 L1 写本轮设计、具体输入、可复核过程、观察和局限。L1 独立阅读时通过方法来源引用补齐上下文。图使用 detail 已登记的固定图片；正文支持明确的 `figure:0`、`figure:1` 图片占位，索引从零开始，前端只调用现有受控 figure API，不将路径变成任意文件访问。没有内嵌占位的旧 detail 保留一次图示补充。

L2 继续记录真实操作、失败和决策；AI 在相邻实验之间引用需要解释的 L2，不逐条复制运行日志。L3 维护可迁移范围，讨论引用它。L4 负责跨实验的论证组织和阶段结论，报告中的 discussion / conclusion 必须位于实验正文之后。附录可交代绘图等环境失败而不打断主实验论证。

### 2. 文稿 API 与证据约束

扩展 `memory document`，保留旧 `items` / `missing` / `basis_heads` 返回，并增加已解析的 `report`。默认选择最近修订的含 report 的 map；调用者可通过明确的 report_record_id 选择，多个候选在回执中列明。章节严格按数组顺序输出，不按层级、标题数字或 UUID 重排。

提交和读取时检查结构、重复章节/重复 detail、固定引用、detail 类型与实验前后关系。引用使用现有服务的固定版本验证，不能绕过来源授权。报告引用旧修订仍以旧正文展示，并明确版本更新提示；正文缺失、撤销或不可访问时给出具体缺口，不静默换成最新结果。没有编排的旧对象显示“尚未编排研究报告”和可展开的记录视图，不冒充已生成完整报告。未纳入报告的新 L1 列为覆盖缺口，不能自动接到报告尾部。

不在读取页面时调用模型，也不重新生成连接语。AI 负责写作，服务负责契约、固定引用和可靠组装。普通检索须覆盖编排的有效正文，仍排除 L0 原始正文。

### 3. 阅读界面

默认显示报告题名、紧凑目录、连续章节和就近图表。正文使用 Markdown/LaTeX 渲染，标题层级规范化；不重复显示 L1 标题、参数表和结果摘要。编号采用报告顺序，L3/L4 标签不占据正文。

提供独立的“记录与来源”折叠区保留按层记录、固定来源、修订和旧版本阅读。目录点击保持工作台路由，长表/公式在窄屏内滚动。图注、未覆盖记录和失效依据不能隐去。

### 4. Skill 与浮点研究重新生成

更新 Research Skill 和记录指南：先划分实验问题与共享方法，再保存 L1/L2，最后用固定回读版本维护 L3/L4 及 report。阶段结束实际回读整篇报告，从头到尾检查重复、过渡、论证顺序、证据覆盖与结论边界。

浮点研究采用相同标准重新生成 L1 和报告，不依赖界面代码硬编码主题或轮次。保留三个原始 Run、后续复算及失败证据，新修订明确事后整理时间；保持 not-reviewed，不将 AI 编辑审查登记为人工批准。保存使用公共 CLI/API，并留实际请求、回执和审核意见。

## 最少必要验收

1. **编排与兼容**：一个小型端到端场景验证 L1 固定引用、prose 顺序、禁止重复/倒置、旧 v1/v2 无 report 回退、旧修订不变、新 L1 未覆盖提示。
2. **证据保护**：复用现有权限/版本/图片测试，增加 report 引用的撤销/缺失/旧修订场景，确保不能通过连接段或引用块泄漏已拒绝正文。
3. **真实阅读**：一项浏览器场景覆盖报告顺序、无重复字段、公式与内嵌图片、目录路由、窄屏；用实际浮点研究截图和逐段内容审核补充，不能只断言标题存在。
4. **交付保护**：前端类型检查/构建/指纹；按现有共享旧工作区 fixture 执行真实 setup 的预览、升级、重复升级与恢复，保护新增编排字段和旧记忆；refresh-index 与 validate。复用已有相关测试，不扩展大规模、模型或全套业务验收。

开发验证只证明上述软件行为；数值结论仍限于固定构造样本。用户的工作台人工审核作为最后独立步骤，未完成前明确待审。
