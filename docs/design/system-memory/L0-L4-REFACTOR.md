# 对象内运行与 L0–L4 研究记录重构

状态：2026-09-09，已进入代码审计与实施。本文覆盖本次用户验收反馈；旧 L0–L3 计划与历史验收保留为历史，不能作为本次实现状态。

## 目标与边界

1. 每个业务对象把自己的实际运行放在对象目录的 `runs/`；根 `runs/` 作为没有业务归属的轻量任务默认位置。Project 组织大型或系统级工作，不为普通计算强建 Project。
2. 插入详细研究记录层，形成 L0–L4。每轮重要研究必须留下可读、可复核的 L1，不能仅用经验或地图替代实际过程。
3. 研究经过完整展示 L1–L4，按问题、方法、参数、结果、讨论与限制组织；数学公式、表格、图示与来源可读。默认不加载 L0 大日志与所有 Run 产物。
4. 材料关系默认展示 L1；L2–L4 可选。默认语义/全文召回使用 L1 以上，L0 通过固定引用展开追溯。
5. 先维护结构与显式归属，再按当前对象组装研究经过，避免每次请求构建全工作区的全部证据图。

## 分层契约

| 新层 | 语义 | 默认保存内容 | 默认发现 |
|---|---|---|---|
| L0 | 原始证据 | 固定输入、脚本、完整输出、日志、环境、版本与哈希 | 不参与普通正文召回；保留来源解析 |
| L1 | 详细研究记录 | 问题、方法、可公开复核的推导和计算步骤、公式与变量、重要入参、图表、观察、失败、限制、L0 引用 | 默认检索与材料关系 |
| L2 | 过程事件 | 尝试、决策及依据、转向、失败分类和下一步 | 默认检索，关系可选 |
| L3 | 复用经验 | 适用条件、不可迁移参数、反例、待验证事项 | 默认检索，关系可选 |
| L4 | 研究地图 | 问题与证据结构、阶段综合、未决事项与导航 | 默认检索，关系可选 |

目标、路线、问题、检查点等辅助记录保留独立语义；不是为了凑齐层数制造虚构结果。保存可核验的推导说明，不保存模型私有思维链。公式用 LaTeX 并定义变量、单位；图片固定到本对象受控附件，引用有来源与指纹。

## 已确认代码与行为缺口

- `workspace_cli.create_run` 强制根目录；旧 `collect_runs` 与 EvidenceGraph 仅覆盖根 runs 和旧 project analysis/runs。Owner 扫描却支持递归，造成入口不一致。
- `contracts.LEVELS` 和 schema 将 source/event/experience/map 固定到旧四层；索引中旧 Run 被映射为 L1 事件。
- Research Skill 当前允许只保存经验或地图，且明确写着没有 L4。本次示例因此缺少逐轮详细过程记忆。
- history 先扫描全体对象，历史版本读取重复验证当前快照与链，关联 Run 再走全局证据图，最后才分页。
- 工作台研究正文主要以 pre 输出；计算公式、图表和结构化结果缺少适合阅读的呈现。

## 兼容性与迁移原则

- 旧修订、提交链、哈希、复核历史和固定引用不得原地改写。版本化契约区分旧层语义与新层语义，展示/索引使用显式有效层级。
- 不自动把原始日志伪装成 L1。旧数据缺详细过程时显示缺口；新 L1 由实际证据整理并新建修订/记录。
- Run ID 维持稳定；新建使用归属目录，旧路径兼容读取。移动现有示例必须先预览、备份、检查引用与哈希，生成路径迁移回执并提供恢复方式。
- 来源路径和对象 ID 分开；移动后仍能验证旧固定字节，不能以重新计算业务结论代替迁移。
- 源码升级保留旧业务树、记忆与用户规则；不得通过忽略未知子目录的真实错误让测试通过。

## 实施分工与顺序

| 工作包 | 负责范围 | 交付与依赖 |
|---|---|---|
| A 对象内 Run | CLI、统一发现、证据图、嵌套运行保护 | 新建归属入口、兼容读取、真实 setup fixture |
| B 分层契约与检索 | schema/contracts、索引/search、类型生成、兼容测试 | 新 L1 detail，版本化 L0–L4，旧数据有效层映射 |
| C 研究经过与界面 | history/必要局部读取、前端正文、材料关系 | 按归属与显式关联组装、可读正文、层级过滤、分页及性能回归 |
| D 集成与说明 | 根代理：迁移、Skill、文档、研究示例与全链验收 | A/B/C 接口核对后补齐示例并按实际 Skill 保存、回读、UI 检查 |

审计先行，接口冻结后各包只编辑分配文件。B 与 C 的共享接口由根代理协调，禁止同时改同一文件。每包完成后报告实际测试，不预填通过。

## 继承并固化的测试点

1. 旧提交字节/record_hash/content_hash不变；旧固定引用、复核、撤回/替代及下游风险继续有效。
2. 单对象提交幂等、无变化、并发 VERSION_CONFLICT、失败恢复；索引 pending 与保存成功分开；不因新层级绕过权限或来源校验。
3. 根 Run、八类对象内 Run、旧 project analysis/runs、多层中文/空格目录、文件型对象、重复 ID 和损坏元数据。
4. 真实 setup 已扩展旧工作区：预览、升级、重复升级、恢复；核对完整文件哈希与空目录存在，含对象内 runs、L0附件与新旧记忆混合。
5. 默认召回不含 L0 正文/日志；固定引用仍能展开；显式排除、预算、范围与正式用途过滤继续有效。旧 Run 的可读摘要与原始产物明确区分。
6. history 不读取无关 Run 的大产物；并发 HEAD 改变、来源失效、缺失引用、restricted数据、未知时间、分页不重漏和撤回后的续接仍受检。
7. UI 显示真实正文而非仅标题/JSON：长公式、表格、图示、中文、失败与缺口；安全 Markdown 不执行脚本、不任意访问本机文件。
8. 查询性能记录冷/热请求、对象数、目标记录数与字节量。建立无关对象增量场景与读取计数断言，不能用只测空目录证明优化；保留实测时间及机器限制。
9. 原检索独立集未通过的历史结论保留；本次新层边界/质量测试单独报告，不能凭软件测试宣布科学模型有效。
