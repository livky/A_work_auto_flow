## 分层目标澄清（2026-09-10）

D08（已被 D09 更正）：讨论中曾将论文式完整正文归入 L0。用户随后明确这是口误：L0 元数据/原始材料追溯不变，L1 完整技术论文块不变，仅修改 L2–L4。保留这段讨论来由，不再沿用“重定义 L0”的方案。

D09（已实施，新内容 v4）：用户同意 L2 研究经过、L3 条目化经验与认识、L4 项目/研究整体概览。L2 保存有依据的路线和转折，操作日志留在 Run；L3 区分观察/结论、假设与建议并保留条件和证据；L4 包含当前阶段、限制和未解决问题。层级不是可信等级，也不要求逐层复制。查询采用“概览与经验”，默认查 L4/L3，需要时展开 L2，再展开 L1；不能只换名称而继续混入细碎正文。新 narrative/overview 与分类 experience 使用 v4；独立文稿 level=null，L0/L1 不变。旧 event/map 保留原语义和固定版本，另写新内容须实际整理，不自动调整层号。

D10（已实现并完成定向软件验证）：主查询从“表示转换”改为内容来源选择：概览与经验查 L4/L3、研究经过查 L2、技术内容查 L1，读取已有正文。展开依明确固定引用，可从经验直接到技术依据；来源选择不等于访问上限，显式排除与原预算仍约束展开。保留旧表示接口兼容。缺内容、缺关联、权限/版本变化和预算不足继续如实报告，不能通过隐藏真实缺口伪装成功。

实施教训：浏览器真实组包发现旧经验的原生 Run claim 虽已登记，却不能经新 Reader 定位。修复为索引定位已知 Owner、读取对应 Run 并逐项核验固定指纹与登记来源，保留撤权/范围拒绝；不构建全库证据图，也不提升结论状态。新增故障回归。新旧契约、来源过滤与展开、界面实操和真实 setup 扩展旧目录已作验证；历史冻结 B01 指纹失败仍单列，不修改冻结材料追求通过。实际 AI/人工/第二物理机分别记录。

## 当前层级收敛与数据迁移（2026-09-11）

D11（已实施并完成浮点研究实际迁移）：用户发现工作台同时显示新旧 L2/L4，浮点研究的新类型内容为空。原因是此前只接通新类型与查询，没有完成既有内容迁移，且遗漏了普通界面入口和部分证据/续接调用方。当前选择是每层只有一个入口，已有内容经实际审查后以同一 ID 的完整新修订迁移；统一写服务只放行 event→narrative、map→overview，并要求前版固定来源、正文与变更原因。历史修订不改写，当前索引替换旧类型。相比创建新 ID 并留下两个当前版本，这样能保持身份和明确的迁移轨迹；代价是必须逐项补正文、展开关系并复核相关调用方，不能通过改名或仅重建索引完成。

实际结果：浮点研究的5条旧事件与1条地图在同一 ID 下生成完整新修订，1条经验补齐关系；7份前版逐项回读一致，FTS/向量均重建到 generation14。真实浏览器确认只有单一 L2/L4 入口且正文可读。前端33项、内容7项、维护20项及新增公开迁移场景、真实升级18项通过；memory 188项中187通过，历史冻结 B01 失败保留。实际查询的默认10秒累计预算不足，显式60秒完成三级读取与组包，未放宽默认值或宣称性能改善。

## 怎样继续维护

D16（2026-09-11，已实施）：按用户七项要求增加标准类型多选、所有来源、5分钟默认活动预算、当前修订默认/显式历史、完整文稿去重、操作区与结果区整理，以及逐项 Skill 闭环。真实浮点研究暴露两个旧边界问题：直接对象范围被误用为必要依据上限，导致有正文却无候选；2 MiB累计读取预算不足以连续组装。现将直接范围与获准必要依据读取分开且保留显式排除，默认16 MiB/8万字符，仍逐次核验权限、版本并累计计量。没有用清零预算或放宽服务端授权解决。历史状态审计按固定依据回读，重新应用仍查当前 HEAD；新图表可选字段两端规范化，避免旧维护回执回填被误判篡改。完整文稿沿已有编排、逐块绑定图像，不增加第二套存储或自动写作。5项真实浏览器与18项真实 setup 升级/恢复通过；性能收益未作对照评估，不宣称提速。3个过时未注册方法原文固定后合并到 research-loop，8个工作区 Skill 逐项审查；用户自定义与全局插件不纳入清理。
