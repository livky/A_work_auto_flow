# 核心算法设计工作流

本工作流仅面向公司算法/模块文档定义的关键模型算法或测校项。先核对 core-algorithms/AGENTS.md 的准入条件，普通软件功能和辅助脚本按工具或流程维护；新算法研究尚无公司文档依据时先保存在 research，不直接建核心算法卡。

已有材料的阅读按根上下文策略：目标算法说明优先，其他证据按必要性加入；证据不足按 workspace-context 方法扩展，不一次加载全部历史。

1. 读取全局 core-algorithms/ 下的 module.json、目标核心算法卡及关联核心算法、接口契约、数据卡、关键 ADR 与验证 Run。
2. 先定义系统目标和核心算法责任，确认上下游、输入输出、shape/type、单位、坐标、时间基准、频率、时延和错误语义。
3. 用 LaTeX 给出方程和符号表，逐项记录假设、参数来源、量纲、不确定度和有效工况。
4. 分离算法核心、IO、编排与展示；配置路径和阈值，不在核心中写死机器/平台细节。
5. 设计三个独立证据面：
   - Verification：实现是否正确求解预期方程/逻辑；
   - Validation：在目标现实条件下是否足够有效；
   - UQ：测量、参数、输入和数值不确定度如何传播。
6. 覆盖边界、异常、饱和、NaN/Inf、收敛、随机性、实时和资源约束；容差必须有工程来源。
7. 影响接口/路线的决定写 ADR；实现与测试形成 Run，核心算法卡引用关键证据。
8. 完成前核对模型—数据—验证三角链接，并刷新索引/运行校验。
