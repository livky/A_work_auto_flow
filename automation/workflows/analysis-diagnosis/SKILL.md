# Analysis Diagnosis 工作流

已有材料的阅读按根上下文策略：目标算法说明优先，其他证据按必要性加入；证据不足按 workspace-context 方法扩展，不一次加载全部历史。

1. 读取全局核心算法入口、相关核心算法卡、数据卡/契约、近期 Run、ADR 与相似复盘；历史相似性只用于生成假设。
2. 明确症状、正常基线、影响范围、时间窗、对象 ID 和成功/证伪标准。原始数据保持只读。
3. 用 `workspace_cli.py new-run` 创建本次证据容器；先记录数据引用、版本/指纹、代码、环境与参数。
4. 优先检查数据边界：schema、单位、坐标、时间同步、标定版本、缺失/异常、重复、过滤、样本选择和上下游版本。
5. 建立候选原因矩阵，每个原因同时记录支持证据、反证、区分性实验、结果和剩余置信度。
6. 大数据先做确定性小样本或聚合验证，再扩展全量；不无界扫描共享盘。
7. 结论区分相关、机制证据与因果判断；记录不能排除的替代解释和适用范围。
8. 若达到事件阈值，起草无责复盘和有 Owner/期限/验证方式的行动项；重复方法晋升为工具或契约检查。

任何外发、原地写数据、设备控制或破坏性动作仍需用户和公司策略授权。
