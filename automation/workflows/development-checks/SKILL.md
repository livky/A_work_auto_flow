# 开发检查

普通工作由work-loop主导；本Skill只补开发需要的验证和维护，不规定实现方法。只要求计划时交付计划，不实施产品。

先通过ARCHITECTURE与实际代码定位受影响模块，查DEVELOPMENT_HISTORY中相关选择；全局架构/工作流整合前完整读历史。按影响读取下表，已有上下文足够不重复加载。修改后核对对应说明和调用者；全局整合、发布或用户要求全面审查时，前后完整阅读六份文档并逐项记录处置。

| 文档 | 何时读取/维护 |
|---|---|
| [README](../../../README.md) | 用户概念、功能、常用入口和目录发生变化 |
| [ARCHITECTURE](../../../ARCHITECTURE.md) | 职责、依赖、状态、数据流与实现差距；全局唯一架构入口 |
| [CORE](../../../docs/CORE.md) | 功能定义、交接、关键行为与调用方式 |
| [docs/README](../../../docs/README.md) | 查详细手册或新增/移动入口 |
| [文档维护](../../../docs/DOCUMENTATION_MAINTENANCE.md) | 规则/Skill/文档职责调整及全面一致性审查 |
| [TESTING](../../../docs/TESTING.md) | 根据风险选测试和维护对应catalog |

测试验证用户行为和真实失败边界，不以文字匹配代替功能；相关检查通过后不机械重复无关全套测试。实际AI、人工、科学结论与软件结果分开报告。执行记录保留实际源码/输入和限制。

接口变化追踪CLI/HTTP/UI、生成类型与Skill实例。前端须类型检查、相关组件/浏览器验证、构建和指纹；涉及发现、安装、缓存或恢复时跑真实setup扩展旧工作区升级/恢复，保护业务及自定义内容；依赖/模型变化按离线分发规范验证。不能把上述边界因“精简”取消。

局部变更逐条核对受影响Skill与直接调用者；入口/契约跨域变化、发布或全面审查时检查所有活跃及兼容Skill的适用时机、真实动作、发现/安装与替代去向。根规则和方法源不重复写完整流程。旧规则/证据保留固定历史，不按名称删除自定义Skill。

完成时在本次计划或Run写清改动、验证、文档/Skill处置及缺口；记录重要决定和被替代的理由。结构变化refresh-index/validate。详细约定按上表读取，不为一次改动新建平行维护清单。
