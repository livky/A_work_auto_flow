# 开发约束与文档入口

适用于含 `workspace.json` 的研发工作区。用户本轮要求和根 AGENTS 优先；本 Skill 只规定项目所需的上下文、验收和维护结果，具体开发方法由任务决定。只要求计划时，交付计划，不进入产品实施。

## 每次开发必读

根规则的 `context/START_HERE.md`、`context/NOW.md` 用于定位当前任务。以下六份短文档须在开发前完整阅读；无需递归打开其中全部链接。

| 路径（相对工作区根） | 承载内容 |
|---|---|
| [README.md](../../../README.md) | 面向使用者的用途、主要概念、目录维护、导入与常用入口 |
| [ARCHITECTURE.md](../../../ARCHITECTURE.md) | 稳定设计约束、当前技术框架、模块落点、依赖关系、状态所有权及实现差距 |
| [docs/CORE.md](../../../docs/CORE.md) | 整体功能块定义、边界与交接，映射 ARCHITECTURE 的模块影响；配人类易读的伪代码、选项差异和实现文件索引，细节按需读代码 |
| [docs/README.md](../../../docs/README.md) | 详细手册、机器契约、历史设计和验证材料的分类索引 |
| [docs/DOCUMENTATION_MAINTENANCE.md](../../../docs/DOCUMENTATION_MAINTENANCE.md) | 文档唯一职责、更新触发及历史保留规则 |
| [docs/TESTING.md](../../../docs/TESTING.md) | 按重要性和改动大小选择验证范围，区分软件、实际 AI 与人工验收 |

受影响模块的详细手册、代码/schema、测试和局部 AGENTS 按索引展开。冻结设计用于追溯，不作为当前接口。开发 Project 的计划和 Run 保存任务证据，不再另维护一份全局架构。

## 讨论方案时必读

每次讨论开发方案前（即使尚未编码），完整阅读 [docs/DEVELOPMENT_HISTORY.md](../../../docs/DEVELOPMENT_HISTORY.md)：理解重要选择的原因、替代方案与代价、历史错误、演进和未决讨论；详细依据按需追溯。实质讨论产生的决定或分歧及时记入；每次开发后与上述六份文档一起重读维护，补实际结果和新教训，保留被替代选择的理由。没有新内容时注明已检查，不为记录而制造决策。

## 必须达到的结果

- 测试覆盖本次行为及关键失败边界。局部低风险改动用轻量核心检查；重要或跨模块改动增加关键功能回归；整体收口按需 full。只有涉及 AI 实际使用、语义判断或续接时才选相应 AI 场景。选择及理由可直接写入任务计划/摘要，复杂执行可用既有 testing 工具，不强制每次跑固定命令链。
- 开发结束后，完整重读上述六份文档，逐项核对当前代码和本次变化，修正文义、概念、功能、模块关系、使用方法及索引；无需变化也明确记为已检查。受影响的细节文档同步维护。未解决项保留原因，不能借改说明把缺陷写成能力。
- 每次开发结束逐条审查工作区 Skill：使用时机、方法源、公开命令/契约、发现入口、安装登记和引用是否仍适配；每条记录修改、核对无需修改或退休及替代入口，具体边界见文档维护手册。仅扫描名称或安装器预览不等于完成语义审查；不维护本工作区之外的全局插件技能。
- 维护结论与实际验证写入本次计划、摘要或既有 Run，避免为相同事实重复建档。失败、未执行、AI 自查与人工待审分别记录；历史依据不改写。结构变化执行 `refresh-index`、`validate`，升级及数据保护触发条件见测试规范。
