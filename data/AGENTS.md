# 数据与血缘规则

## 硬边界

- `data/` 只保存数据引用、卡片、契约、血缘和获批小样本，不保存公司原始大数据。
- 真实数据默认只读；任何删除、覆盖、移动、权限修改或外发都需要明确授权。
- 不扫描未知规模的共享盘根目录。先限定数据集、时间窗、字段、文件模式和最大数量。

## 数据资产

- 每个稳定输入/输出有唯一 `DATA-*` ID 和一个 `*.dataset.json`。
- `uri` 优先使用受控别名或位置模板；若真实路径敏感，用机器本地配置解析。
- `digest` 可以是内容哈希、目录清单哈希、数据库快照 ID 或设备批次 ID；必须注明算法与覆盖范围。
- 数据卡与契约必须记录单位、坐标/参考系、时间基准、采样、标定版本、缺失/异常语义和敏感等级。

## 质量

- 契约把规则分为 `error`、`warning`、`observe`。
- 质量结果写入 Run 的结构化字段，不只打印日志。
- schema 变化、单位变化、字段重命名和标定版本变化默认视为潜在破坏性变更。

## 血缘

- 使用 Entity（数据/模型/报告）、Activity（采集/清洗/分析/仿真/生成）和 Agent（人/脚本/系统）的最小语义。
- 事件至少记录：event_id、time、activity/run、inputs、outputs、agent、code/version、status。
- 不在血缘中写明文凭据、个人敏感数据或不必要的真实内部路径。
