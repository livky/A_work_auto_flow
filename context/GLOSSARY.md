# 术语表

| 术语 | 定义 | 注意事项 |
|---|---|---|
| 数据卡（Data Card） | 对数据来源、含义、组成、限制、责任与推荐用途的说明 | 回答“这是什么、能否用” |
| 数据契约（Data Contract） | 对 schema、单位、质量、兼容性、SLA 与敏感等级的机器可读约束 | 回答“必须满足什么” |
| 核心算法 | 公司算法/模块文档定义的关键模型算法，具有工程目标、模型方法、接口与适用边界，可通过子系统协同实现 | 不等同于脚本函数、软件模块或通用工具 |
| 核心算法卡（Core Algorithm Card） | 上述算法项的文档来源、接口、方程、假设、V&V/UQ 与失效模式说明 | module.json、MOD-ID 和 --module 等沿用兼容字段名，只指核心算法 |
| Run | 一次不可混淆的分析、仿真、标定、训练、诊断或报告生成实例 | 回答“这一次发生了什么” |
| Verification | 验证实现是否正确求解了预期方程或逻辑 | “方程解对了吗” |
| Validation | 验证模型在目标现实条件下是否足够有效 | “方程代表现实吗” |
| UQ | Uncertainty Quantification，不确定度识别、传播和汇总 | 必须标注来源与置信含义 |
| 血缘（Lineage） | 实体、活动与执行者之间的使用、生成、派生和归属关系 | 可对齐 W3C PROV/OpenLineage |
| ADR | Architecture/Algorithm Decision Record，重要技术决策记录 | 旧决策不删除，标记被替代 |
| 候选记忆 | AI 或人工尚未复核的总结、提示和经验 | 不能覆盖正式事实源 |
| 正式知识 | 有来源、适用范围、验证状态和责任人的版本化内容 | 可用于后续决策 |
| 控制平面 | 当前工作区内的小型元数据、代码、契约、计划和知识 | 应可版本化与检索 |
| 数据平面 | 共享盘、数据库、计算平台中的大数据和大产物 | 通过引用和指纹连接 |

添加术语时避免只写缩写；若不同团队用词冲突，应保留别名和适用域。

## 检索与组织术语

| 术语 | 定义 |
|---|---|
| Project | 可选目标/交付视图，不拥有算法副本 |
| Research | 独立问题与证据集合，可关联多个核心算法和 Run |
| Embedding | 成熟模型将文本映射成数值向量，无需先训练 |
| Qdrant local | 本地持久化向量检索库，当前单进程使用，无 HTTP 服务 |
| RAG | 检索相关资料，供生成模型依据资料回答的工作方式；不是单独的模型 |
| 全文 / 片段 | 上下文装载单位，与向量索引切片单位不同 |
| OCR | 从图片提取文字，不能代替对图表含义的理解 |

| 上下文调查 CTX | 一次带阶段、选择、预算、来源指纹的阅读记录；后续扩展指向父 CTX |
| Q 查询 | 一次检索候选快照，可有单份来源反馈 |
| brief | 从长 Run 选择原始字段的摘录，不是模型生成的新结论 |
| 一致性差异 | 文档和代码可能不同的线索；需核对版本与行为，不自动判定哪方错误 |
