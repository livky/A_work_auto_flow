# AI 研发工作区

用于管理算法文档、代码、实验记录和研究知识的本地研发工作区。通过版本引用、证据检索和复核记录，将问题分析、实验验证与报告交付连接起来，支持 AI 辅助研发中的追溯与复用。

## 主要功能

- **材料管理**：登记已有文档、代码和数据来源，维护关键词、版本及关联关系。
- **检索与分析**：结合全文和本地向量检索，按问题选择算法说明、实现代码、历史实验和研究资料。
- **实验记录**：以 Run 保存一次分析或验证的输入、配置、产物、结论和限制。
- **证据查看**：查看结论的保存原因、来源、复核历史、失效风险及受影响报告。
- **材料关系**：以辐射、主题聚合和证据链浏览材料，按需发现关键词、语义与结构联系，向 AI 导出局部关系摘要。
- **变化监测**：检查材料变更、实验完成和依赖风险，生成待处理的维护候选。
- **部署与迁移**：支持 Windows 一键安装、保留业务数据的框架升级及离线迁移。

## 快速开始

### 安装

支持 Windows 10/11 x64。从 GitHub 下载 ZIP 并完整解压，在解压目录打开终端，执行：

```powershell
.\setup.cmd --register --open
```

默认安装便携 Python、依赖和本地模型，完成检查后打开工作台。使用配套离线依赖包时，把 `dependencies-windows-x64.zip` 和同名 `.zip.sha256` 放在解压后的源码根目录，再执行上述命令；安装器自动校验、导入本地环境，无需联网或预装 Python。没有配套依赖包时，首次完整安装联网下载。仅使用证据查看、变化监测等基础功能时，可添加 `--profile core`；该模式跳过完整依赖包。

### 打开工作台

首次注册后重新打开终端，执行：

```powershell
rdwork
```

也可在工作区根目录直接运行：

```powershell
.\workbench.cmd
```

工作台提供材料关系、模块文件清单、证据查看、监测启停和环境检查。持续监测需手动开启，每 60 秒检查一次；使用 Ctrl+C 停止服务，关闭浏览器标签页不会结束服务。使用机台无需安装 Node。

### 升级已有工作区

关闭旧工作区中运行的工作台、索引和实验进程，在新版解压目录执行：

```powershell
.\setup.cmd --target "D:\研发\旧工作区" --register --open
```

升级保留旧工作区中的业务数据、配置和记录，并备份被替换的框架文件。升级后继续使用旧工作区目录。添加 `--preview` 可查看计划。

源码目录中的配套依赖 ZIP 同样用于升级；也可显式指定 `--bundle "D:\下载\dependencies-windows-x64.zip"`。依赖按新版锁文件校验，旧运行时和模型备份后再替换，最后自检并按旧工作区的材料来源重建索引。

命令注册使用一个固定的用户 PATH 项，重复注册更新工作区地址。执行 `.\setup.cmd --unregister` 可撤销注册并保留数据。

安装选项、保留范围和恢复方法见 [一键部署与工作台](docs/SETUP_WORKBENCH.md)；离线打包与迁移见 [Windows 离线迁移](docs/WINDOWS_PORTABILITY.md)。

### 分发本机依赖

在已安装完整环境的工作区执行：

```powershell
.\setup.cmd --pack-dependencies --apply
```

生成 `dist/dependencies-windows-x64.zip` 和校验文件，可作为 GitHub Release 附件。包含便携 Python、锁定的第三方包、Qdrant local、嵌入与 OCR 模型；按发行清单取文件，排除业务材料、数据库、查询历史与未登记本机文件。打包不下载依赖，也不自动上传。分发及恢复方法见 [依赖包与 Release](docs/DEPENDENCY_RELEASE.md)。

### 体验示例数据

```powershell
.\workbench.cmd workbench --demo
```

示例覆盖算法、数据、实验、研究、知识和报告之间的关联。生成数据保存在独立的 `.local/test-workspace/` 中，重复打开保留编辑；示例数据不参与正式证据检索，也不进入 Git 或离线包。

## 日常使用

### 导入材料

向 AI 提供材料路径、用途和允许处理的范围，使用 `$context-maintenance` 分批整理。导入过程登记来源、阅读进度、关键词以及文档与代码的版本关系，将材料关联到已有算法或研究，并保留冲突和提取失败项。

原始数据保留在获批存储中，工作区保存引用和受控证据。材料写回后更新检索索引；后续修订通过版本关系和依赖检查识别影响。操作示例见 [材料导入与变更](docs/EXISTING_MATERIALS.md)。

### 分析问题

使用 `$workspace-context`，说明目标算法、具体问题及指定或排除的材料。分析优先读取算法说明，再按需要补充代码、Run 和研究资料。上下文按“聚焦 → 核对 → 扩大”逐级扩展，保留读取范围与预算约束，并列出证据缺口。

有独立输入和结果的分析保存为 Run，记录输入版本、配置、产物与结论。可复用结论经适用范围内的复核后整理到算法卡或知识库。检索配置和反馈用法见 [上下文与检索手册](docs/RETRIEVAL.md)。

### 浏览材料关系

在工作台进入“材料关系”，首次点击“构建 / 刷新材料视图”。搜索材料并设为中心，可切换问题辐射、主题聚合和证据链，查看连线依据、预览来源或排除材料。按需运行关键词、语义相似及聚类，通过“复制关联摘要”将当前范围交给 AI。

视图分组和候选保存在本机；相似度、聚类和 AI 建议不改变正式证据状态。操作与命令见 [材料关系手册](docs/MATERIAL_RELATIONS.md)，开发扩展见 [工作台开发](docs/WORKBENCH_DEVELOPMENT.md)。

### 查看证据与变化

在工作台打开证据页，或使用 `$evidence-inspection` 查看结论来源、复核记录和报告依赖。工作台支持单次检查和持续监测，首次检查建立基线，后续记录变化事件与维护候选。

监测结果用于提示需要检查的内容，候选合并、证据复核与可信状态更新需分别处理。“已记录”“执行成功”“结论已复核”分别保存；正式报告应引用固定 Run，并核对来源版本、适用范围和复核依据。

详见 [证据查看与监测](docs/EVIDENCE_VIEW_MONITOR.md) 和 [证据准入手册](docs/EVIDENCE_CONTROLS.md)。

### 常用技能与命令

仓库技能入口位于 `.agents/skills/`，方法正文位于 `automation/workflows/`。支持仓库技能的客户端可使用以下调用；首次加载可能需要重新打开会话。

| 技能                     | 用途                                   |
| ------------------------ | -------------------------------------- |
| `$context-maintenance` | 材料导入、版本与关联维护、批次进度保存 |
| `$workspace-context`   | 算法问答、文档与实现核对、证据检索     |
| `$evidence-inspection` | 证据查看、变化监测、报告影响检查       |

所有 CLI 子命令均可通过 `rdwork` 或 `.\workbench.cmd` 调用：

```powershell
rdwork --help
rdwork doctor
rdwork index-knowledge --dry-run
rdwork index-knowledge
rdwork evidence-monitor --dry-run
rdwork refresh-index
rdwork validate
```

## 核心概念与目录

核心算法、研究、Run 和工具独立组织，通过稳定 ID 和引用关联；项目用于聚合交付目标。同一结论维护主要正文，其他位置通过引用复用。

| 目录                       | 内容与维护方式                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| `core-algorithms/`       | 公司算法或模块文档定义的关键模型算法。算法卡维护模型说明、文档来源、实现版本与适用边界     |
| `runs/`                  | 独立分析、仿真或验证的记录。保存输入、配置、产物和复核状态；新分析建立新 Run，纠错保留历史 |
| `research/`              | 专题研究的计划、文献、证据台账与综合结论；实验结果引用 Run                                 |
| `knowledge/`             | 可复用经验、决策与复盘；维护依据、适用范围和修订历史                                       |
| `projects/`              | 可选的交付目标、里程碑与进度，引用相关算法、研究和 Run                                     |
| `tools/`                 | 可复用脚本、代码包与适配器；工具登记记录入口和用途                                         |
| `data/`                  | 数据卡、字段与单位契约、流转关系；原始大数据保留在获批存储中                               |
| `reports/`               | 报告需求、源文件、模板、生成件和证据映射；正式数字关联固定 Run                             |
| `retrieval/`             | 检索配置、来源登记、评估与反馈；索引随材料变化增量更新                                     |
| `context/`               | 工作区导航、当前状态、记录规则与交接信息；重点变化时更新                                   |
| `context/monitor/`       | 本机监测基线、变化事件与维护候选；观察历史不随 Git 发布                                    |
| `services/qdrant/`       | 本地 Python、Qdrant、嵌入模型、OCR 及检索存储；安装与升级由部署工具管理                    |
| `.local/`                | 本机示例工作区、安装引导与升级备份；不进入 Git 或离线包                                    |
| `automation/`            | 命令行工具、工作台、测试与工作流；随功能变更维护                                           |
| `inbox/`、`archive/`   | 待整理材料与冷存档；按任务范围整理和归档                                                   |
| `governance/`、`docs/` | 数据边界、治理规则与使用手册                                                               |

各目录中的 `_template/` 用于创建记录。`MOD-*`、`RUN-*` 等 ID 标识对象，文件移动时保留其身份和引用关系。
