# AI 研发工作区

用于管理算法文档、代码、实验记录和研究知识的本地研发工作区。通过版本引用、证据检索和复核记录，将问题分析、实验验证与报告交付连接起来，支持 AI 辅助研发中的追溯与复用。

## 主要功能

- **材料管理**：登记已有文档、代码和数据来源，维护关键词、版本及关联关系。
- **检索与分析**：结合全文和本地向量检索，按问题选择算法说明、实现代码、历史实验和研究资料。
- **实验记录**：以 Run 保存一次分析或验证的输入、配置、产物、结论和限制。
- **版本记忆**：为已有业务对象保存可追溯修订，提供全文与向量检索、研究经过、问题与目标演进、阶段总结、纠错、暂停续接及单对象迁移。CLI/API 和工作台已接入；本轮执行已收口，整体质量与人工验收状态以[执行状态](docs/design/system-memory/STATUS.md)为准。
- **证据查看**：查看结论的保存原因、来源、复核历史、失效风险及受影响报告。
- **材料关系**：以辐射、主题聚合和证据链浏览材料，按需发现关键词、语义与结构联系，向 AI 导出局部关系摘要。
- **变化监测**：检查材料变更、实验完成和依赖风险，生成待处理的维护候选。
- **部署与迁移**：支持 Windows 一键安装、保留业务数据的框架升级及离线迁移。

## 快速开始

多轮研究示例见浮点求和的数值稳定性（本地历史记录，未随源码分发：`research/floating-point-summation/README.md`）：三轮探索分别保存详细文稿、公式、参数、图表及固定 Run，版本记忆保留过程事件、经验和研究地图。继续探索时在研究内新增 Run，再更新研究台账与综合结论，保留原始记录。

### 安装

支持 Windows 10/11 x64。从 GitHub 下载 ZIP 并完整解压，在解压目录打开终端，执行：

```powershell
.\setup.cmd --register --open
```

默认安装便携 Python、依赖和本地模型，完成检查后打开工作台。使用配套离线依赖包时，把 `dependencies-windows-x64.zip` 和同名 `.zip.sha256` 放在解压后的源码根目录，再执行上述命令；安装器自动校验、导入本地环境，无需联网或预装 Python。没有配套依赖包时，首次完整安装联网下载。仅使用证据查看、变化监测等基础功能时，可添加 `--profile core`；该模式跳过完整依赖包。

### 打开工作台

首次注册后重新打开终端，执行：

```powershell
rdwork
```

也可在工作区根目录直接运行：

```powershell
.\workbench.cmd
```

工作台提供材料关系、对象记忆、研究经过与续接、跨研究检索、模块文件清单、证据查看、监测启停和环境检查。持续监测需手动开启，每 60 秒检查一次；使用 Ctrl+C 停止服务，关闭浏览器标签页不会结束服务。使用机台无需安装 Node。

对象记忆中的类型勾选框支持任意组合：默认全选，多选显示并集，可一键全选或清空。导出与当前筛选一致；清空后不显示记录并禁用导出。

勾选“L0 原始材料”可浏览 Run 已登记的输入、脚本、产物和独立来源，研究会汇总显式关联的 Run。同文件与版本合并显示使用关系，点击“核验并查看原件”读取有界文本或图片。已有附件不必再登记一次 source；导出 L0 保存固定材料清单。

“登记”就是记录文件在哪里、属于哪次实验、是什么用途，以及当时的文件指纹。你可以直接让 AI “执行实验并把完整材料保存到 L0”：新 Python 实验用 `run-execute` 自动保存输入、输出和失败日志；已有文件或其他工具结果用 `run-register` 自动计算指纹，不必手工改 run.json。每次执行的原始结果和恢复回执保存在 Run 内 `.run-captures/`，升级时保留；恢复登记不删除原文件。范围、请求示例与限制见[实验执行与自动登记](docs/RUN_CAPTURE.md)，分层职责见[记录标准](docs/RESEARCH_RECORDING.md)。

八类对象、根 Run、对象内 Run 和每次执行回执的区别，以及默认保存位置与 Skill 分工，见[对象与运行保存逻辑](docs/OBJECT_RUN_STORAGE.md)。

### 升级已有工作区

关闭旧工作区中运行的工作台、索引和实验进程，在新版解压目录执行：

```powershell
.\setup.cmd --target "D:\研发\旧工作区" --register --open
```

新版源码应解压到独立目录，新旧目录不得互相嵌套。升级保留旧工作区中的业务数据、配置、原规则、自定义 Skill 和版本记忆，并备份被替换的框架文件。升级后继续使用旧工作区目录，不直接用新目录覆盖旧目录。添加 `--preview` 可查看计划。

源码目录中的配套依赖 ZIP 同样用于升级；也可显式指定 `--bundle "D:\下载\dependencies-windows-x64.zip"`。依赖按新版锁文件校验，旧运行时和模型备份后再替换，最后自检并按旧工作区的材料来源重建索引。

跨机器交付使用“新版源码 ZIP + 配套依赖 ZIP + 校验文件”，接收端不需要逐个安装第三方包。仅提供源码不会自动替换旧模型；模型更新必须携带匹配依赖包。当前自动模型迁移限于约定名称、路径和兼容的 384 维模型，不能据此推断任意模型均可升级。重建索引只更新派生检索结果，不修改原材料或重验业务结论。失败应检查恢复回执；框架和依赖分别用 `--rollback`、`--rollback-dependencies` 恢复，修改过的目标文件会受到指纹保护。

命令注册使用一个固定的用户 PATH 项，重复注册更新工作区地址。执行 `.\setup.cmd --unregister` 可撤销注册并保留数据。

安装选项、保留范围和恢复方法见 [一键部署与工作台](docs/SETUP_WORKBENCH.md)；离线打包与迁移见 [Windows 离线迁移](docs/WINDOWS_PORTABILITY.md)。

安装失败时先查看最早的具体校验错误，也可在目标工作区运行 `workbench.cmd validate` 单独排查，见 [升级错误排查](docs/SETUP_WORKBENCH.md#排查升级校验错误)。

历史文档可能引用未随源码分发的本机日志；链接 warning 本身不会阻止安装，但需区分历史附件与业务材料缺失，见 [历史链接警告](docs/SETUP_WORKBENCH.md#历史文档的链接警告)。

开发者修改校验或部署逻辑时，应运行包含用户新增子目录和自定义工具的升级回归，见 [升级测试约定](docs/UPGRADE_TESTING.md)。

### 分发本机依赖

在已安装完整环境的工作区执行：

```powershell
.\setup.cmd --pack-dependencies --apply
```

生成 `dist/dependencies-windows-x64.zip` 和校验文件，可作为 GitHub Release 附件。包含便携 Python、锁定的第三方包、Qdrant local、嵌入与 OCR 模型；按发行清单取文件，排除业务材料、数据库、查询历史与未登记本机文件。打包不下载依赖，也不自动上传。分发及恢复方法见 [依赖包与 Release](docs/DEPENDENCY_RELEASE.md)。

### 体验示例数据

```powershell
.\workbench.cmd workbench --demo
```

示例覆盖算法、数据、实验、研究、知识和报告之间的关联。生成数据保存在独立的 `.local/test-workspace/` 中，重复打开保留编辑；示例数据不参与正式证据检索，也不进入 Git 或离线包。

## 日常使用

### 导入材料

向 AI 提供材料路径、用途和允许处理的范围，使用 `$context-maintenance` 分批整理。导入过程登记来源、阅读进度、关键词以及文档与代码的版本关系，将材料关联到已有算法或研究，并保留冲突和提取失败项。

原始数据保留在获批存储中，工作区保存引用和受控证据。材料写回后更新检索索引；后续修订通过版本关系和依赖检查识别影响。操作示例见 [材料导入与变更](docs/EXISTING_MATERIALS.md)。

已有知识接入版本记忆时，先关联已有研究、Run 或知识对象。没有稳定 ID 的平铺文档可以显式“采用”，创建旁目录中的 `OBJ-*` 身份，正文保持原样。需要从原文提取经验时先固定来源版本并预览草案，明确适用条件、不能迁移的部分和未知字段，再保存；后续总结引用已有记录，避免复制多份无版本关系的结论。具体步骤与单对象导入流程见 [版本记忆使用指南](docs/MEMORY_USAGE.md)。

### 分析问题

使用 `$workspace-context`，说明目标算法、具体问题及指定或排除的材料。分析优先读取算法说明，再按需要补充代码、Run 和研究资料。上下文按“聚焦 → 核对 → 扩大”逐级扩展，保留读取范围与预算约束，并列出证据缺口。

有独立输入和结果的分析保存为 Run，记录输入版本、配置、产物与结论。可复用结论经适用范围内的复核后整理到算法卡或知识库。检索配置和反馈用法见 [上下文与检索手册](docs/RETRIEVAL.md)。

### 浏览材料关系

在工作台进入“材料关系”，首次点击“构建 / 刷新材料视图”。搜索材料并设为中心，可切换问题辐射、主题聚合和证据链，查看连线依据、预览来源或排除材料。按需运行关键词、语义相似及聚类，通过“复制关联摘要”将当前范围交给 AI。

视图分组和候选保存在本机；相似度、聚类和 AI 建议不改变正式证据状态。操作与命令见 [材料关系手册](docs/MATERIAL_RELATIONS.md)，开发扩展见 [工作台开发](docs/WORKBENCH_DEVELOPMENT.md)。

### 查看证据与变化

在工作台打开证据页，或使用 `$evidence-inspection` 查看结论来源、复核记录和报告依赖。工作台支持单次检查和持续监测，首次检查建立基线，后续记录变化事件与维护候选。

监测结果用于提示需要检查的内容，候选合并、证据复核与可信状态更新需分别处理。“已记录”“执行成功”“结论已复核”分别保存；正式报告应引用固定 Run，并核对来源版本、适用范围和复核依据。

详见 [证据查看与监测](docs/EVIDENCE_VIEW_MONITOR.md) 和 [证据准入手册](docs/EVIDENCE_CONTROLS.md)。

### 保存经验、纠错与继续研究

使用 `$research-loop` 时，AI 将实验、方法、推导或分析保存为 L1 技术单元。单元包含供检索的简要说明和可独立引用的完整正文块；实验绑定固定 Run，方法与推导不必虚构一次运行。独立章节选择固定技术块并补上必要定义，文稿组织章节、目的、读者和范围。L4 继续维护研究地图。

工作台“研究经过”可切换完整研究过程与精简研究报告：前者保留逐轮论证，后者集中呈现问题、方法、关键结论与边界。两份文稿共享固定依据，各自维护结构。按章读取上下文或检查更新影响，可以定位需要调整的章节；新增单元不会自行进入报告，来源新修订也不会自动替换。旧文稿继续可读。见[研究文档设计](docs/design/RESEARCH_DOCUMENTS.md)及[记录标准](docs/RESEARCH_RECORDING.md)。

在记忆页选择已有对象，填写正文、保存原因、来源和适用边界，先预检后保存。普通修改增加修订，历史正文与回执保留。经验中的具体结论可使用 `CLM-*` 单独复核；记录保存成功、运行成功和结论已复核是三个不同状态。

探索检索用于发现相关经验和待核对线索，正式检索需要给出适用范围并通过当前证据检查。导航关联、相似度和 AI 总结不能让结论自动获得正式资格。阶段巩固与跨项目总结固定输入对象的版本，保存前再次检查，避免把过期材料包当作当前依据。

暂停时保存检查点，继续时读取目标、路线、未解决问题和所需输入。纠错通过反馈或复核变更留下原因，必要时撤回或替代结论并检查下游；不要删除旧正文来掩盖失效过程。

保存回执同时返回规范保存状态和索引状态。出现 `INDEX_PENDING` 时可能已经成功保存，可按 ID 读取并用 `memory reconcile` 补偿；不要因为检索暂不可见而再次创建相同业务记录。CLI 入口、错误码、恢复、可读导出与迁移包的区别见 [版本记忆使用指南](docs/MEMORY_USAGE.md)。

### 常用技能与命令

仓库技能入口位于 `.agents/skills/`，方法正文位于 `automation/workflows/`。支持仓库技能的客户端可使用以下调用；首次加载可能需要重新打开会话。

安装技能时，如果同名文件含用户修改，安装器会在写入整个批次前停止，保留现有文件，并显示当前内容与新版建议的合并差异。按差异合并所需更新后再重试；自定义技能继续保留。

| 技能                     | 用途                                   |
| ------------------------ | -------------------------------------- |
| `$context-maintenance` | 材料导入、版本与关联维护、批次进度保存 |
| `$workspace-context`   | 算法问答、文档与实现核对、证据检索     |
| `$research-loop`       | 专题研究、逐轮详细记录、实验验证与阶段综合 |
| `$development-checks`  | 开发前更新分级测试选择，执行回归及实际 AI 自查、人工审查 |
| `$evidence-inspection` | 证据查看、变化监测、报告影响检查       |

所有 CLI 子命令均可通过 `rdwork` 或 `.\workbench.cmd` 调用：

```powershell
rdwork --help
rdwork doctor
rdwork index-knowledge --dry-run
rdwork index-knowledge
rdwork evidence-monitor --dry-run
rdwork refresh-index
rdwork validate
rdwork memory --help
rdwork memory list-owners
```

## 核心概念与目录

核心算法、研究、Run 和工具独立组织，通过稳定 ID 和引用关联；项目用于聚合交付目标。同一结论维护主要正文，其他位置通过引用复用。

版本记忆采用L0–L4：L0是用于追溯的原始证据，L1是包含参数、公式、计算说明、图表结果和限制的详细研究记录，L2是过程事件与决策，L3是复用经验，L4是研究地图。Research默认按实质轮次保存L1和实际L2，在阶段结束检查五层覆盖；经验不足时明确缺口，不编造结论。问题、目标、路线、检查点等保持辅助契约。默认知识检索使用L1以上，L0按固定引用展开；旧四层记录保留原字节、版本和哈希，以新语义投影展示。见[分层记录标准](docs/RESEARCH_RECORDING.md)。

Run保存到开展工作的对象内部：`new-run --owner RES-ID`写入对应研究的runs/；根runs/仅作为无归属轻量工作的默认位置。Project用于系统级或大型工作。旧根Run与旧项目路径继续兼容，不为目录整理改写历史证据或复制同一次实验。

| 目录                       | 内容与维护方式                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| `core-algorithms/`       | 公司算法或模块文档定义的关键模型算法。算法卡维护模型说明、文档来源、实现版本与适用边界     |
| `runs/`                  | 无明确归属的轻量分析及历史 Run；新分析优先保存到所属对象的 `runs/`，纠错保留历史 |
| `research/`              | 专题研究的计划、文献、详细说明、对象内 Run、证据台账与综合结论 |
| `knowledge/`             | 可复用经验、决策与复盘；维护依据、适用范围和修订历史                                       |
| `projects/`              | 可选的交付目标、里程碑与进度，引用相关算法、研究和 Run                                     |
| `tools/`                 | 可复用脚本、代码包与适配器；工具登记记录入口和用途                                         |
| `data/`                  | 数据卡、字段与单位契约、流转关系；原始大数据保留在获批存储中                               |
| `reports/`               | 报告需求、源文件、模板、生成件和证据映射；正式数字关联固定 Run                             |
| `retrieval/`             | 检索配置、来源登记、评估与反馈；索引随材料变化增量更新                                     |
| `context/`               | 工作区导航、当前状态、记录规则与交接信息；重点变化时更新                                   |
| `context/monitor/`       | 本机监测基线、变化事件与维护候选；观察历史不随 Git 发布                                    |
| `services/qdrant/`       | 本地 Python、Qdrant、嵌入模型、OCR 及检索存储；安装与升级由部署工具管理                    |
| 对象内 `memory/` 或材料旁记忆目录 | 服务维护 `owner.json`、`HEAD.json`、不可变提交和回执；普通用户通过工作台/CLI编辑，不直接改文件或清理事务目录 |
| `.local/memory-migrations/` | 单对象导入暂存与恢复回执；恢复先核对指纹，只处理本次创建且未修改的文件 |
| `.local/`                | 本机示例工作区、安装引导与升级备份；不进入 Git 或离线包                                    |
| `automation/`            | 命令行工具、工作台、测试与工作流；随功能变更维护                                           |
| `inbox/`、`archive/`   | 待整理材料与冷存档；按任务范围整理和归档                                                   |
| `governance/`、`docs/` | 数据边界、治理规则与使用手册                                                               |

各目录中的 `_template/` 用于创建记录。`MOD-*`、`RUN-*` 等 ID 标识对象，记忆记录使用 `MEM-*`，结论使用 `CLM-*`。移动已有记忆对象时使用显式迁移映射，保留身份与固定引用；手动搬动文件后由路径重新猜测身份会被拒绝。全文、向量与材料视图是可重建的派生索引，不能代替原登记、规范记录或复核历史。
