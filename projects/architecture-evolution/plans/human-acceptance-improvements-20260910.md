## 已确认的分层与查询目标（2026-09-10）

最终以用户最后两次澄清及“对，按你说得来”为准：**L0/L1 保持现状，只调整 L2–L4；L2 为研究经过，L3 为经验总结，L4 为整体概览。** 此前将完整正文归入 L0 的讨论已被用户纠正，不能继续作为设计依据；原人工检查表保持原字节。

| 层级 | 职责与内容边界 |
|---|---|
| L0 | 保持元数据与原始材料追溯；原始数据、来源和实际执行事实不搬成摘要 |
| L1 | 保持完整技术论文块：方法、推导、实验、数据与依据；检索说明和完整块现有分离方式不因本次目标取消 |
| L2 | 有依据的研究经过：问题、路线选择、关键实验、失败、判断与转折，以及如何形成经验；引用 L1，详细操作日志留在 Run |
| L3 | 条目化经验与认识：观察/结论、原因假设、建议与下一步方向分别表达；保留适用条件、限制及证据，不把假设和建议写成已验证经验 |
| L4 | Project/Research 整体概览：主题、关键方法、主要结果、重要失败与启发、当前阶段、限制及未解决问题；允许研究尚未完成 |

层级表示内容职责，不表示可信程度，不要求逐层复制。L3 可直接引用 L1，L4 可引用 L2/L3；事件、日志、已有关系图也不因改层号就变成研究脉络或整体概览。现有独立章节/完整文稿/精简文稿不自动改为某一层，实施前明确它们如何引用这些内容，避免新建平行正文权威来源。

查询入口采用 **“概览与经验”**：默认候选来源为 L4/L3；需要过程时显式展开 L2，需要技术复核时展开 L1。各次展开继承原范围、排除、权限、用途和预算，返回固定引用与缺口。不是先全量检索 L1 再裁成摘要；缺 L3/L4 时说明缺口并提供展开/整理入口，不悄悄混入细节或现场生成未登记结论。更名及旧 CLI/HTTP 参数兼容方案在实现中明确。

用户随后确认具体方案：主查询撤下“表示方式”选择，改为“概览与经验 / 研究经过 / 技术内容”的来源选择；读取记录已有正文，预览截短只影响展示。展开沿明确的固定引用读取其他记录，允许从 L3/L4 直接读 L1，不强制逐层经过，也不凭同 Owner 猜测依据。召回来源选择与访问/排除范围分别表达；缺正文、缺关联、权限变化与预算不足分别报告，不再把不满足旧摘要配方的材料混作可读候选。旧表示接口保留兼容，语义生成仍为单独保存任务。

当前实现仍是 memory-v3：L2 事件、L3 经验、L4 地图；独立章节/文稿 level=null。目标与实现差异主要在 L2/L4 的内容职责及查询来源约束，不是简单互换两个数字。旧内容需按实际语义检查，不能全局替换层号或重算旧指纹。

## 实施边界、维护与验收

按 1 → 2 → 3 → 必要的 4 → 5 推进；第 6 项单独排期。第 2 项先形成小型契约/兼容设计和固定样例，再实施，不再重复询问已确认的层级职责。

- 维护规则：由 AI/人根据实际 L1/Run 与来源编写 L2–L4，通过公开预检/提交/回读保存；任务阶段、证据或结论变化时审查相关过程、经验和概览。更新保存为新版本，依赖固定引用；来源变化不自动改正文、改可信状态或追认研究成功。
- 兼容：核对旧 event/experience/map 与新职责的差异；能复用的固定引用复用，需要语义整理的另建/修订记录并保留关联。实际迁移先预览范围，保留旧版和恢复依据，不把旧 map 直接标为新概览。L0/L1 原内容和固定引用保持；缺材料时明确延期，不补造正文。
- 模块影响：MEM 的版本契约/旧版读取，DOC 的研究经过/文稿组合，RET/MQ 的来源过滤与展开，EVD 的固定证据/准入，APP 的名称、选择与进度，GUIDE 的研究/查询/维护 Skill，QA 的基线与升级保护。实际依赖按 ARCHITECTURE 检查，本计划不复制全局影响图。
- 行为验收：反选后候选集合与实际组包一致；结束原因区分已遍历本次候选窗口、预算、取消与错误；进度总量未知时显示真实完成状态，不伪造百分比。
- 内容验收：固定样例包含一次失败、一次路线转折、未验证原因和未完成研究。L2 能解释推进理由，L3 分开观察/假设/建议，L4 保留阶段与缺口，且都可追溯 L1/Run。
- 查询验收：默认不返回 L0/L1/L2 为概览候选；显式展开可获得所需过程/正文，并保持排除、权限、正式用途和预算。缺少概览/经验、来源撤权、旧版内容、取消与预算终止均有负例。
- 质量与成本：固定相同小型/中型语料、问题和期望来源，对比相关性、召回、错误关联、实际读取量、上下文量及延迟；在计划中先写本次可接受标准，再运行，保留不满足项。万条规模仍暂缓。
- 测试维护：真实 H02/H03/H16 故障和新增行为登记 catalog；逐项判断基线准入/已有覆盖/按影响执行及原因，复审受影响的既有防线，不因清单已有测试就认定覆盖。前端重建资源及指纹；涉及 schema/安装保护边界时按升级约定做真实扩展旧工作区验证。

本次对齐的实际产出为本计划 v3 和开发决策 D09；仅做文档一致性与链接核对，不作为以上产品验收通过。六份现行入口保持现有实现描述，目标统一在本计划，后续实现后同步更新。
