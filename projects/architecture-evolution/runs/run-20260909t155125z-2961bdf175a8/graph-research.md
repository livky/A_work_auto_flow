# 图与逐步检索的抽象能力边界

图检索值得保留的稳定能力，是**允许从不同材料表示进入、沿有语义的关联扩展、回到固定版本的原文，并在可控预算内说明已经找到什么与还缺什么**。HippoRAG 2、LightRAG 和 DRIFT 分别提供了关联传播、不同抽象表示、逐步问题扩展的实例；现有证据不足以选择一个作为所有任务的默认实现。

本稿讨论能力与约束，供后续接口、数据结构和调用关系设计使用；所列能力是设计建议，不表示已经实现或已经批准具体 API。搜索分档按用户澄清解释为材料抽象程度，预留 L0–L4 之外由外部选择的表示。自动整理可按授权策略修订正式知识，版本、复核与恢复能力应随之保留。

## 1. 三条路线提供的证据

| 路线 | 原始材料中的机制与结果 | 证据边界 |
| --- | --- | --- |
| HippoRAG 2 | 将短语节点与段落节点共同用于个性化 PageRank；查询先匹配并过滤三元组，最后取回段落。论文中 MuSiQue 的 passage Recall@5 从 NV-Embed-v2 的 69.7 提升到 74.7；过滤后没有短语种子时退回向量检索。[^1] | 这是特定语料、模型和配置的实验。论文资源表中，11,656 段落的索引时间为 99.5 分钟，而向量基线为 12.1 分钟；不能据此预测本地设备速度。传播得分本身也不是事实证明。[^1] |
| LightRAG | 低层侧重具体实体，高层侧重关系和主题，结合图与向量检索。论文在四类 UltraDomain 数据上使用 LLM 成对评价；对 GraphRAG 的 Overall 胜率为 54.8%、52.0%、52.8%、49.6%。[^2] | 四组结果并非全面胜出，且评价口径不是原文证据 Recall@K。高层、低层是内容表示与检索方向，不能直接等同于知识复核等级。[^2] |
| Microsoft GraphRAG DRIFT | 从相关社区报告形成初答和追问，再做局部搜索，形成问题与回答的层次。2024 年官方实验使用 5,000 多篇 AP 新闻、50 个局部问题和 LLM 评审，全面性、多样性胜过 Local Search 的比例分别为 78%、81%。[^4] | 该实验支持“高层信息可以指导局部问题展开”，不证明事实正确率、来源完整率或企业权限隔离。发布文章当时设置两轮展开，不能直接固化成现行默认值。[^4] |

当前官方实现进一步说明，可替换策略需要可观察的执行边界。LightRAG 的 `QueryParam` 分别提供模式、实体/段落候选数、不同上下文 token 配额、重排与仅返回上下文选项。[^3] DRIFT 文档公开查询状态和分词器等组件；所查 `search.py` 按 `n_depth` 循环、限制每轮追问数，在没有未完成动作时退出，并汇总模型调用与 token 使用。[^5][^6] **记录消耗不等于在调用前强制执行全过程预算**，后者仍应成为本系统独立讨论的能力。

## 2. 建议稳定下来的功能边界

以下属于由证据与当前需求形成的设计推论，尚未进行本地实现验证。

| 能力 | 需要稳定表达的约束 | 可由外部选择或替换的部分 |
| --- | --- | --- |
| 选择材料表示 | 支持声明可用表示、请求表示与实际返回表示；明确表示的来源和生成版本。L0–L4 可作为现有命名，但不封闭为唯一枚举。材料抽象程度、知识角色、复核状态与有效性分别表达。 | 标题、摘要、专题综述、社区报告、实体、关系、详细内容、原文等表示；表示的组合与检索顺序。 |
| 指定入口与种子 | 可从自然语言、固定文档/记录引用或已发现节点开始；种子保留来源、匹配方式与作用范围。调用者指定的种子仍需受范围校验。 | 查询改写、三元组匹配、主题匹配、关键词或向量匹配；种子权重与截断方式。 |
| 限定范围与权限 | 在读取节点、邻居及摘要之前执行范围与权限约束；返回证据时再次确认。派生摘要必须能确认其贡献来源均适用于当前可见范围，否则重新生成、选用授权表示或报告不可用。 | 项目、来源、时间、版本、记录类型等筛选组合，以及授权范围内的路由。 |
| 区分关系语义 | 至少区分导航关系、模型抽取的事实候选、来源支持/冲突关系及版本或计算依赖。关联强度、相关性、置信度和人工/自动复核结果不得共用一个含义模糊的权重。 | 同义边、共现边、实体关系边、文档层次边、来源依赖边；图数据库与存储布局。 |
| 返回证据与路径 | 返回固定原文引用和可检查的关联步骤，标注直接证据、派生说明、冲突及缺失引用；路径解释由可审计记录组成。摘要或图边只能支持其实际表达的主张。 | 返回单条或多条支持路径、路径压缩方式、图浏览与文本展示。 |
| 控制预算 | 区分候选数、读取量、上下文 token、模型调用、时间、步骤等预算；说明已用、预留和剩余量，允许取消与返回部分结果。预算针对整个请求及各阶段，不能被追问或续查悄悄重置。 | 预算分配、并发度、先广后深或先深后广；不同质量/成本策略。 |
| 保存逐步检索状态 | 查询目标、所选表示、已读引用、待展开项、去重信息、使用预算与快照/水位需要可恢复；恢复时重新核验授权及版本条件。 | 前沿队列的实现、追问生成、状态存放介质与过期时长。 |
| 排序与重排 | 每个候选保留产生渠道、排名、分数含义和模型/策略版本。不同模型分数不能未经校准直接解释为同一概率或真值。 | 向量排序、PPR、关键词、融合、交叉编码器、LLM 重排与多样性选择。 |
| 说明停止原因 | 至少区分证据暂时足够、无新增证据、无可展开项、预算耗尽、被取消、来源不可用及执行错误。不能把“停止”统一写成“已找到答案”。 | 新证据判断、启发式充足性评估、深度阈值与奖励模型。 |
| 支持知识自动修订 | 正式知识可由获授权的整理策略修订；应保留变更前后版本、采用证据、策略版本、复核状态、下游影响和恢复入口。检索形成的高分候选不能自动改变其可信状态。 | 自动整理触发器、合并/拆分/摘要策略、适用自动复核流程和恢复策略。 |

由此，稳定边界应围绕“请求范围和表示—取得候选—按缺口展开—返回有来源的结果与停止状态”组织。是否采用图、采用何种图以及扩展多少轮，是这一能力边界内部的策略选择。后续接口设计再确定对象、字段与调用关系，当前不预设一个巨大的统一检索函数。

## 3. 材料抽象与证据回源的关系

“专题摘要 → 实体/关系 → 详细内容/原文”可以是一种可选择的检索路径，也可以直接从原文或实体进入。外部调用者需要能选择表示与展开方式，不应被要求知道某个特定图算法的参数。

例如，用户查找“某方案为何被替代”：专题综述可以定位讨论范围；版本关系可以找到新旧方案；详细记录与原文则承担验证原因、适用条件和反证的工作。如果综述只说“效果更好”，原文却限定于某次测试，最终结果必须保留这个限定。社区重要性、传播权重或排名再高，也不能把该测试结论升级为普遍事实。

对于摘要、关系、向量等派生表示，建议保留可重建所需的来源引用、生成配置及版本信息。更新正式记录后，可以重建其派生表示；删除或撤回一份来源时，需要区分“移除这份来源的贡献”和“删除由多份来源共同支持的实体”。这也是自动整理与检索读取之间需要明确的边界，而非某种图数据库专属的要求。

## 4. 需要保留的反例与验证问题

下表是拟用于后续接口讨论和小规模验证的判别场景，不是已经通过的测试。

| 场景 | 要观察的行为 | 可以区分的设计问题 |
| --- | --- | --- |
| 单份原文已能直接回答 | 能直接返回原文；图展开增加的成本可见 | 图检索是否被错误设为所有请求的强制前置步骤 |
| 多跳问题包含同名实体 | 种子与路径暴露身份依据，允许回退或保留歧义 | 排名很高是否掩盖错误连接 |
| 高层摘要遗漏版本条件 | 展开后能补回条件，最终引用固定版本 | 摘要是否替代了原文证据 |
| 同一社区包含不同可见范围材料 | 未授权内容不进入摘要、邻居扩展和输出 | 权限是否只在最终文本阶段过滤 |
| 两份材料对同一事实冲突 | 分别保留来源、时间与适用域，返回冲突状态 | 图合并或重排是否消除了必要反证 |
| 预算在追问中耗尽 | 返回已完成结果、未解问题与剩余状态 | 追问是否形成无法控制的递归调用 |
| 续查期间知识发生修订 | 保持快照或显式切换版本，更新成本和影响可追溯 | 逐步结果是否悄悄混合不兼容版本 |
| 自动整理撤回或拆分知识 | 保留旧版、恢复入口及派生表示更新记录 | 正式知识修订是否可追踪、可复核、可恢复 |

效果验证宜将原文证据命中、引用支持程度、冲突保留和回答质量分开，再同时记录索引成本、查询时间及模型调用。论文中的 LLM 偏好胜率与证据召回率不宜相互替代。只有在相同授权语料、固定版本、代表性问题及相同成本口径下比较，才能决定本地默认策略。

## 5. 当前结论的适用范围

可据此进入下一步讨论的，是可扩展材料表示、范围控制、固定来源、关系语义、执行状态、预算、停止原因及可追溯修订等能力。尚不能据此确定某个框架、模型或图后端，不能承诺本地吞吐、正确率或自动整理可靠性。当前官方仓库按访问时的滚动分支观察，未固定提交；正式实现前需要选定提交并复核其契约。
