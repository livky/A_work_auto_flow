# 材料查询七项优化：实际结果

## 已实现

1. 结构按8类标准 Owner 单选/多选，支持对象名称查找；类型与具体身份相交，空集合与显式排除保留。
2. 所有来源覆盖获准已登记内容、文稿、章节、来源和原生 Run；默认仍查概览与经验。
3. 默认活动执行预算5分钟；真实连续组装暴露2 MiB读取不足，因此默认读取16 MiB、输出8万字符。保持服务端上限、累计计量与取消，不清零重试。
4. 默认 current 只取当前修订，缓存回读再核验；allow_stale 才扫描有界历史，旧版本标记及固定引用保留。
5. documents 按同一文稿身份合并多个命中，按既有章节与技术块顺序返回正文和图示；展开可带正文、必要上下文与已启用的有效补充。
6. 常用动作位于候选上方并保持可见；右侧显示本次输出，后续失败清除旧正文并显示对应回执。
7. 逐项审查8个工作区 Skill，更新3项；3个过时未注册方法保留原文后退休，独特指导并入 research-loop。详见 SKILL_AUDIT.md。

## 关键实现与真实故障

MQ 复用原规范存储和索引。catalog_search 负责全来源目录候选，history_search 有界检查历史，documents 定位文稿并去重；Coordinator/Reader 统一核验与计量。没有引入新数据库、模型或后台任务。

真实浮点研究最初无结果，原因是界面把直接 Research 范围同时作为必要依据上限，引用的 Run 被拦。现在直接筛选与必要依据读取分开；工作台明确显示跨对象依据开关，关闭即可收紧，排除项与服务端授权始终优先。来源/层级筛选不误拦文稿或必要技术定义。

重复组装此前耗尽2 MiB累计预算；保持逐次权限/版本核验，依据完整文稿与连续动作的实际读取需求调整默认额度，没有把缓存读取当免费或用新查询冒充原查询续接。新增图表保留每个技术单元自己的 figure:N，Reader 校验受控文件、SHA及读取预算，避免合并文稿后的图号错配。

维护历史状态审计使用固定依据，不因提交后旧版本不再是当前而丢失历史回执；再次应用仍查当前HEAD。新增可选 figures 字段造成旧计划回填默认值不一致，已两端按同一契约规范化；正文、图像、引用和回执的实际改动仍拒绝。
