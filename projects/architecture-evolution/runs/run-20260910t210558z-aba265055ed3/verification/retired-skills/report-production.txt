# Report Production 工作流

1. 读取 `reports/README.md` 和报告 brief；若 brief 不完整，补齐受众、决策、三条关键信息、格式、截止与敏感等级。
2. 只从已验证或明确标注限制的 Run/研究/数据中提取数字与图表；不得把报告中的手填值变成新事实源。
3. 建立 report manifest，记录报告 ID、源文件、模板版本、Run/数据 ID、引用、生成时间、产物和哈希。
4. 按交付格式使用相应文档、演示或 PDF 工作流；关键图表的数据、单位、分母、时间窗和变换必须可复核。
5. 结构上先给结论与行动，再给证据、备选解释、限制和下一步；面向管理层减少实现细节，面向技术评审保留复现入口。
6. 生成后做结构与视觉 QA：封面、密集页、关键图、表格、引用、结尾、字体、裁切、重叠和乱码。发现缺陷后修订并再次验证该缺陷。
7. 对外、管理层或安全关键材料必须人工审阅和批准；在 manifest 中记录状态。

没有公司模板时使用克制的临时视觉系统，并明确标记待替换，不虚构品牌规范。
