## 如何维护

开发开始时在影响图定位本次变化的模块，沿关联检查调用方、索引投影、文稿、用户入口、Skill、测试和迁移。结果写入本次 Run 的影响清单，每项分别标为“需修改”“已检查无需修改”或“延期及原因”。模块职责或接口变化时，修订影响图并在本次 Run 保存固定快照和哈希；普通措辞修订无需增加图版本。

图的箭头表示“此处变化会要求另一处重新检查”，不等同于全部 Python import，也不代表自动执行或自动验证。通用操作约定见[文档与影响维护](../../docs/DOCUMENTATION_MAINTENANCE.md)。

## 保存与发行

本项目的 Run 位于 `runs/`，不复制已有研究或历史实验。当前影响图、计划和时间线属于可修改项目文档；Run 中的快照是对应时点的固定证据，不作为另一份现行规则。

本项目保留在完整工作区/checkout 中；既有 `git archive` 规则排除 Project 实例，公共源码包仅携带通用维护手册、规则、模板和当前[架构说明](../../ARCHITECTURE.md)。离线升级保留目标工作区已有项目；本轮增加材料查询的受控发行文件和Skill入口，并通过真实扩展旧工作区场景检查保护与恢复。没有进行Git提交或对外发布。
